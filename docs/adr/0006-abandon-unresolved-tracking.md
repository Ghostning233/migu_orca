# 未决结果允许用户显式放弃跟踪

「结果待确认」的记录在恢复之前被删除守卫完全拦死：用户实测有 5 次未决期间删除被守卫拦截，最终都靠只读核验才收敛（其余恢复出口并未消失，只是删除出口被锁）。本决策把守卫的判据从"记录状态"收窄到"**外部写是否可能仍在执行**"：写仍在执行时依旧禁止，写已结束而结果不可知时，允许用户在显式接受风险后放弃跟踪。

## 决策

1. **按操作状态判定，不按记录状态判定，且无法判定时一律 fail closed。** 完整判据：

   | 关联 operation 的状态 | 删除 |
   | --- | --- |
   | `IN_PROGRESS` | **拒绝**——外部写可能仍在 Auto Bangumi 执行，丢弃记录等于丢掉唯一线索（与 [ADR-0002](0002-risk-confirmed-manual-resubmission.md) 第 5 条一致，本决策不修改它） |
   | `PREPARED` | **拒绝**——它可由另一个执行者转入 `IN_PROGRESS`，此刻"不是 IN_PROGRESS"不构成证明 |
   | `OUTCOME_UNKNOWN` / `RECOVERY_REQUIRED`（且已非上述两者） | **允许**，走第 2 条的风险确认 |
   | operation 缺失、损坏、读取失败或取值未知 | **拒绝**——沿用既有守卫的 fail closed 行为，不得因为"读不出来"而放开 |
   | 无关联 operation | 按既有语义处理 |

   `OUTCOME_UNKNOWN` **不等于**证明 Auto Bangumi 远端已停止处理：调用超时后远端仍可能继续处理。允许放弃的是「本地外部调用已退出、结果仍不可判定」，不是「远端确定没有动作」。

2. **放弃跟踪是一次显式风险确认，不是静默放行。** 确认必须**绑定条目 + revision + 当前 operation**；删除执行时在服务端**原子重验**（revision 与 operation 均未变化），以免与 `PREPARED → IN_PROGRESS` 的转换竞跑。任一条件变化即拒绝该过期确认。确认文案必须说明：这次提交的结果无法确认，Auto Bangumi 中可能已经建立了订阅并会继续下载；删除后 MiGuOrca 不再跟踪它，也不会再提醒。
3. **只读核验优先于放弃。** 进入未决状态时先自动执行一次只读核验；能定论就直接定论。界面上「再核验一次」排在「放弃跟踪并删除」之前，且核验必须可一键重试。
4. **人工标记退役。** 「标记为成功／标记为失败」要求用户自行到 Auto Bangumi 中查证，属于把核验负担转嫁给用户，从产品中移除；不因此缩减只读核验与审计能力。
5. **更安全的路径仍然存在。** 未决的持续追番提交仍可走 ADR-0002 的「主动重发」：它保留原记录与审计、先只读核验、并以 `previous_operation_id` 关联新操作。放弃跟踪是最后出口，不是首选。本决策不退役「主动重发」，也不把自动只读核验当作它的授权。
6. **放弃跟踪只在单条路径提供，且只删除本地。** 不得在放弃流程中勾选「同时删除外部订阅」——那会把一次放弃变成一次新的外部写，重新落回本决策要解决的循环。

## 后果

- 未决记录不再是永久卡死状态；代价是可能留下一条 MiGuOrca 不再可见、却在 Auto Bangumi 中继续运行的订阅（同步对非受控对象只计数、不接管，见 [ADR-0005](0005-no-full-autobangumi-takeover.md)）。
- 删除只移除本地方案快照与追番记录，其审计事件随之消失；`tracking_operations/` 中的操作文件保留为孤儿证据。
