# MiGuOrca 不追求全面管控 Auto Bangumi

MiGuOrca 是 Auto Bangumi 的前置订阅编排工作台，不是它的上层管理面板。当前阶段的核心能力是「搜索并添加番剧」；把 AB 中已有的、非 MiGuOrca 创建的订阅导入并接管，不在当前范围内。

## 决策

1. **同步只比对，不收养。** 同步把 Auto Bangumi 的订阅列表与本地记录对照，用来确认本地受控订阅在外部是否仍然存在、是否仍然启用。AB 中不属于 MiGuOrca 控制的对象只被计数，不创建、不导入、不刷新本地记录，也不产生任何外部写。
2. **「仅外部」（`EXTERNAL_ONLY`）状态退役。** 它原本是为「全面管控」预留的：表示 MiGuOrca 记录了一条自己没有本地方案的外部订阅。既然不收养，它就没有产生路径，从界面与产品语义中移除；schema 的兼容处理单独评估，不随本决策一并删除。
3. **「外部已删除」（`EXTERNAL_DELETED`）保留。** 它表达的是同步检测到的事实：原本受控的外部订阅已不存在，而本地方案与记录仍在。它是异常事实的如实记录，不是主动管理能力，因此归入「需处理」。
4. **本决策不削减安全能力。** 同步缺失判定、审计事件、未决结果恢复与只读核验都必须保留；未来若要补齐全面管控，需重新评估本决策，不得以「暂不接管」为由删除上述能力。

## 后果

- 「我的追番」不再需要用户手动触发同步；同步改为只读、自动执行，具体时点由界面规格决定。
- AB 中非受控订阅继续以计数形式呈现，界面不提供接管入口；这会让「同步摘要」里的「忽略 N 条不属于 MiGuOrca 的外部订阅」成为一条长期存在的信息。
