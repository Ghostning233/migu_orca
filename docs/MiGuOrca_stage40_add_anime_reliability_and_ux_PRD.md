## 2. 分期、目标与非目标

### Stage 40：草案可靠性（F1，P0）

先消除“修改成功后无法保存确认”的阻断，独立审核通过后才可开始改变加载和编辑体验。此阶段不重画页面、不改变 API、不改变保存语义。

### Stage 41：添加页状态反馈与任务导向审核（D0、F2～F4）

在 D0 完成设计资产基线后，逐步交付加载反馈、服务端草案自动重算和六图所指向的添加页/共享详情层级。F4 不得在 F3 的草案状态机通过独立审核前启动。

### Stage 42：非阻断反馈收尾（F5，最后）

仅在前两阶段稳定后将短时全局提示改为悬浮 Toast；不得借此隐藏字段、候选、条目或批量失败反馈。

全阶段共同目标：保留人工选择真实 MiKan 合集、服务端草案权威、两次确认（本地保存确认与追番管理外部提交）、敏感字段白名单和“已更新集数：待开发”。

共同非目标：不增加数据库、worker、多用户/移动端、qB 下载、真实 MiKan 用户配置、伪实时百分比、从 RSS/种子推断已更新集数，且不把未保存现场恢复到刷新后。

## 3. 已核实的事实与冻结约束

1. `POST /api/v1/requests/preview-modify` 已支持 `draft_id + base_revision + patch`；允许的 patch 只有 `selected_subtitle_group`、`filter_rule` 与 `expected_folder_name`。成功返回同一草案能力和递增的 `draft_revision`，不落盘；过期 revision 返回 `draft_revision_conflict`。前端不能发送完整 Request 当权威快照。
2. `POST /api/v1/requests/save-confirm` 与批量 `POST /api/v1/batches/{batch_id}/save-confirm` 都只接收草案能力、revision 和内存幂等键。批量的预期逐项失败仍为 HTTP 200 的 `results[]`；成功项不因其他项失败回滚，失败草案可重试。
3. 现有安全详情只有 `GET /api/v1/requests/{request_id}/safe-info`，其输入是**已保存** Request 的 `request_id`。未保存草案只有 `request_id=null` 和允许额外字段的显示快照，不能把它伪装成服务端 `safe-info` 白名单。
4. 现行单番 `useSingleAnimeJourney` 的快照是非响应式内部变量；`SingleAnimeReviewPanel` 的 `saveButtonDisabled` 又先调用 `journey.canConfirm()`，因此静态分析支持 FE-01 的响应式依赖丢失假设，但 F1 必须先用连续回归用例证实，再以最小修复收口。
5. 批量搜索契约一次返回 parse 结果，未提供逐条实时进度；UI 只能表达整体进行中、完成后的逐项状态和已知局部失败，不能画百分比或逐项实时进度。

## 4. 产品缺口与需用户决定事项

### D40-01：未保存草案的“全部信息”

用户已于 2026-09-17 确认保守方案：未保存审核页不调用 `safe-info`，不要求与已保存方案等价的“全部信息”弹窗；只在默认/按需展开区域显示从当前草案快照经前端显式安全投影得到的必要字段，且不称为服务端安全详情。保存后仍使用既有 `safe-info`。

本路线不新增草案安全投影 endpoint、DTO、serializer、OpenAPI/generated client 或其安全契约测试。将来若产品改变该决定，必须另立后端工作包，不能在本 Stage 顺带加入。

### D40-02：批量“局部重试”含义

当前契约支持的是**保存确认**后仅重提仍失败、仍可确认的条目；批量 parse/candidate search 没有单条重搜端点。Stage 41 只能提供已有的整批重新搜索，以及对已返回候选逐条生成草案/重试生成。若要“仅重搜一个 FAILED 解析项”，需新后端契约，未经决定不得实现或在文案中承诺。

## 5. 原子工作包、故事与停止条件

### WP-40-A / US-341：F1 单番修改后保存确认可靠性

**目标：** 从修改规则、成功 `preview-modify`、新 revision 到 `save-confirm` 的完整单番路径保持可确认；按钮的 disabled 状态与就地说明必须来自同一响应式状态源。

**非目标：** 不引入自动重算、不改文案层级、不调整批量，不改 save-confirm 或草案 API。

**依赖：** 当前 `useDraftSession`、`useSingleAnimeJourney`、`SingleAnimeReviewPanel` 与既有 generated 契约。

**可观察验收条件：**

- 先新增能在修复前失败的连续测试：生成草案（revision=1）→ 修改规则 → 成功返回 revision=2、有效资源 → “保存并确认”变为可点击且说明同步为“可用”；点击请求准确携带同一 `draft_id` 和 `base_revision=2`。
- 修改进行中、存在未提交表单编辑、无字幕组、无有效资源、草案失效、修改失败、revision 冲突、保存中分别禁用主按钮并显示对应的中文就地原因；不会出现灰色按钮同时宣称“可用”。
- `draft_revision_conflict` 仍按现有安全恢复语义回到重新选择合集，不显示原始错误、草案能力或服务端内部文本。
- save-confirm 成功仍只建立本地待提交 tracking 记录；不产生 Auto Bangumi 外部写。

| 单番状态 | 主按钮 | 就地提示 / 后续动作 |
| --- | --- | --- |
| 草案一致、有效资源、无待编辑 | 可用 | “保存并确认可用” |
| preview-modify 在途 | 禁用 | 正在重新计算订阅方案 |
| 表单待应用 | 禁用 | 有尚未应用的编辑 |
| 成功返回新 revision | 恢复可用 | 使用新 revision，不保留旧提示 |
| 修改失败（可重试） | 禁用 | 修改未生效；重试或恢复上次结果 |
| revision/draft 失效 | 禁用且离开审核 | 重新选择合集 |
| 无资源/字段阻断 | 禁用 | 具体可修复原因 |

**定向验证：** `WorkbenchView.test.ts`/`SingleAnimeReviewPanel` 定向 Vitest，`useSingleAnimeJourney.test.ts` 的响应式回归，`npm run typecheck`、`npm run lint`。真实 Chromium：以 held `preview-modify` 路由验证在途禁用；fulfill revision=2 后断言按钮与说明一致并检查 save-confirm body；另覆盖冲突和零资源。禁止用 handler sleep，且检查 DOM、URL/history、storage、console 不含草案能力或敏感值。

**停止条件：** 最小红测未能证明问题、修复需要改变 API/保存确认语义，或连续路径仍不同步时停止并回到评审；独立审核未通过不得开始 WP-41-B。

**非目标：** 不改前端、不覆盖或删除图、不移动仍现行的批量 V2、管理 V2、两张异常状态 V1 或本次六图；不进行浏览器验证。

**依赖：** 新版效果图文档与 `frontend-ux-visual-direction-v1.md`；开始前全库 `rg` 引用盘点。

**可观察验收条件：** 所有 Markdown/文档链接有效、旧图只作为历史参考、现行添加首页唯一指向六图；Git 中保留图的历史，不留断链。

**定向验证：** `rg` 盘点旧/新路径、Markdown 链接检查（若项目已有脚本则使用该脚本）；仅文档检查。

### WP-41-B / US-343：F2 候选与减少动态效果的加载反馈

**目标：** 单番和批量候选生成都在被点击的候选旁展示明确、就地、可恢复的加载状态；减少动态效果时不留下含义不明的静止半圈。

**非目标：** 不添加逐项搜索进度、不改变候选选择的人工确认边界、不通过全局 Toast 代替候选附近的错误。

**依赖：** WP-40-A；复用 `CandidateCollectionList`/`CandidateCard`，但必须给其增加按候选/按批量 item 的公开 loading 输入，而非另造卡片。

**可观察验收条件：**

- 普通动效下 loading spinner 连续旋转；`prefers-reduced-motion: reduce` 下保留可读的“处理中/正在生成草案”文字及 `aria-busy`，不依靠静止残缺圆弧表达进行中。
- 单番一次仅可发起一个候选生成：被点卡片按钮就地加载，其他候选暂禁但不被标记为加载；失败留在该候选附近并可重试。
- 批量只锁当前 item 的候选生成；其他 item 仍可查看、选择或编辑，且不会被错误标成加载。成功后该 item 原子进入草案状态。
- 候选阶段不显示有效资源数；资源数只在草案生成成功后显示。

| 场景 | 单番 | 批量 |
| --- | --- | --- |
| 点击候选 | 当前按钮加载、同会话其他选择禁用 | 当前 item 候选加载，其他 item 不锁 |
| 成功 | 进入单番审核 | 仅当前 item 进入 DRAFT、右栏更新 |
| MiKan/网络/解析失败 | 候选旁安全错误和重试 | 当前 item 候选旁安全错误和重试 |
| 减少动态效果 | 文字仍表达进行中 | 同左，不画伪进度 |

**定向验证：** `CandidateCollectionList`/`CandidateCard`、`WorkbenchView`、`BatchWorkbenchView` 受影响 Vitest，typecheck/lint。真实 Chromium：单番点击第一候选并 held create-request；批量在一项 held 时操作另一项；普通与 reduced-motion 各验证一次；失败后就近重试。

**停止条件：** 必须新增逐条实时接口、无法隔离批量 item 锁、或发现候选公共 DTO 缺失必要显示字段时停止；不得用假的百分比或全页 loading 代替。

### WP-41-C / US-344：F3 服务端权威草案自动重算与“保存修改”

**目标：** 将字幕组和影响资源的过滤规则统一为服务端权威的自动草案修改；保留“保存修改”作为提交尚未自动提交内容的次操作，明确它不保存本地方案。

**非目标：** 不新增 preview endpoint，不把 Request 快照放入浏览器持久化，不让最终“保存并确认”隐式吞掉未知待编辑；不把目录修改说成资源重算。

**依赖：** WP-40-A；现有 preview patch 足够支持本工作包，无后端改动前提。F4 必须消费本包完成的单一状态机。

**冻结交互语义：**

- 更换字幕组立即发送 `preview-modify`。
- `must_contain`、`must_not_contain`、`use_regex`、`case_sensitive` 属于过滤规则；每次最后输入/切换后 1.5 秒防抖发送。
- `expected_folder_name` 不影响资源筛选，不自动发送；“保存修改”立即提交它，以及尚未到期的过滤输入。此按钮仅更新服务端**内存草案**，完成后仍须“保存并确认”。
- 存在防抖等待、草案请求在途、失败未恢复或手工待提交字段时，“保存并确认”禁用并说明原因；不在最终确认点击时暗中发送第二个请求。

**可观察验收条件：**

- 每次请求都以最新 `draft_id + base_revision` 发出；成功一次性提交服务端返回的 request、资源摘要、字幕组/规则和新 revision。不得显示“新选择 + 上次有效资源”为已生效。
- 同一 item 在请求在途时不复用 revision 发送第二个 CAS；新的输入保留为待处理，在当前请求完成后仅对仍最新的意图继续调度。切换批量详情、离开/失效时取消 timer 并令旧响应无效，旧响应不能覆盖新 item。
- 失败保留最后一个服务端一致结果，并把用户新意图标成“尚未生效”；提供重试、恢复上次结果。冲突/草案失效按重新生成恢复，不泄漏内部错误。
- 资源变为零时进入阻断态，原有效资源不再被称为当前有效；批量保留勾选意图但暂不计入可确认数。
- 单番详情、批量卡片和右栏详情读取同一条目状态；任何入口成功后 revision 与资源摘要同时更新。

| 编辑/传输状态 | 显示的结果 | 保存修改 | 保存并确认 |
| --- | --- | --- | --- |
| 无待修改且服务端一致 | 当前服务端资源 | 禁用 | 若无其他阻断则可用 |
| 字幕组立即提交/规则 1.5 秒等待 | 上次一致结果 + 正在等待/更新 | 可立即 flush 待规则/目录 | 禁用 |
| preview 在途 | 上次一致结果 + 正在更新 | 防重禁用 | 禁用 |
| 成功 | 新配置、新资源、新 revision 原子替换 | 无手工待提交则禁用 | 按资源/字段状态决定 |
| 可重试失败 | 上次一致结果 + 新意图未生效 | 重试/恢复入口 | 禁用 |
| 冲突/草案失效 | 不继续渲染为可确认 | 不可用 | 不可用，重新生成 |

**定向验证：** `useDraftSession`、新增编辑调度 composable（若拆出）、`AnimeDraftEditor`、单番/批量 host 的 Vitest；fake timers 验证 1.5 秒、连续输入、flush、取消和乱序；断言请求 revision 递增且没有完整 Request。typecheck/lint。真实 Chromium：字幕组立即更新、规则防抖、快速连续输入、切换批量 item、held 旧响应、失败重试/恢复、冲突、零资源及最终 save-confirm 被阻断的场景。

**停止条件：** 现有 endpoint 不能表达所需 patch、无法保证 CAS/revision 与显示原子性、或产品要求最终确认隐式提交待编辑时停止并请产品重新决定；不得靠前端猜 revision 或接受旧响应。

### WP-41-D / US-345：F4 添加页与共享审核详情的信息层级

**目标：** 在已稳定的状态机上，把单番首页、候选、单番审核、批量左卡右详情改成六图指定的任务导向层级；单番和批量共用同一审核核心，完整种子按组缩进。

**非目标：** 不逐像素复刻图片、不更改 API、不扩展未保存 `safe-info`、不改追番管理/设置、不实现“已更新集数”。

**依赖：** WP-41-A、B、C；D40-01 按默认保守方案执行，除非用户选择后端扩展。

**可观察验收条件：**

- 单番初始页聚焦名称输入和模式切换，未搜索时没有空结果大面板；直连合集仅在无结果后的次级救援入口，人工选择真实合集不变。
- 候选只显示公开封面、标题、季度证据、总集数和选择动作；季数冲突就近解释。草案生成前不显示资源结论。
- 审核默认回答“已选哪部/哪一季、筛后有什么、能否确认”：已选合集、字幕与资源摘要、筛选规则、阻断原因、保存确认。技术 ID、原始标题、RSS 选择、英文区名和诊断不在默认层；高级设置和完整种子按需展开。
- 未保存详情不用 `safe-info` API；保存后的方案详情继续复用严格安全白名单。任何显示都不渲染 URL、magnet、绝对路径、原始响应、草案能力或秘密。
- 完整种子中字幕组为一级，组内资源为二级缩进；长标题、1280 宽度和键盘 `<details>` 展开仍可读。
- 批量当前查看只切换右栏，复选框只改变保存范围；固定操作栏是唯一批量主“保存并确认 N 部”入口。部分成功时成功/失败/未处理计数、焦点和仅失败项重试遵从既有交互规格。

| 页面状态 | 必须可见的安全反馈 | 禁止行为 |
| --- | --- | --- |
| 单番初始/搜索中/空/失败 | 输入保留、整体进行中或就地错误、下一步 | 未搜索即展示空结果；伪进度 |
| 候选生成中/失败 | WP-41-B 的候选旁加载/重试 | 显示资源数；自动选合集 |
| 草案一致/重算中/失败/零资源 | WP-41-C 的资源一致性与阻断理由 | 新配置配旧资源；只靠 Toast 提示错误 |
| 批量局部保存成功 | 成功项待提交，失败项原位可修复，汇总与焦点 | 回滚成功项；重提成功项；把 HTTP 200 当整批成功 |
| 未保存草案“全部信息” | 默认无服务端 safe-info 弹窗 | 用 null request_id 调 safe-info 或把快照称安全白名单 |

**定向验证：** 所有变动组件 Vitest，文案/选择器同步搜索现有 `WorkbenchView.test.ts`、`BatchWorkbenchView.test.ts` 和 `tests/browser/test_app_*.py` 断言；typecheck/lint/build。真实 Chromium：1440×900、1280 和宽桌面；单番初始/候选/审核，批量 1、约12、36 项及部分成功，长标题、键盘焦点、空结果/零资源、敏感 DOM canary。浏览器测试在实施期按 `dev-browser` skill 运行，不在本规划期运行。

**停止条件：** 需要未保存 safe-info 后端能力、批量单条重搜、额外公开 DTO、或设计要求与安全白名单冲突时停止对应故事并回到 D40-01/D40-02；不得用 mock 字段、隐藏 CSS 或接口别名绕过。

### WP-42-A / US-346：F5 悬浮全局提示收尾

**目标：** 将非关键短时全局反馈改为不会推动页面布局的悬浮 Toast，并为替换、自动关闭和加载结束建立可验证生命周期。

**非目标：** 不把关键错误、重试、字段校验、候选/条目状态从原位置移走；不改变业务 API 或 notification 的安全脱敏边界。

**依赖：** Stage 41 完成及稳定的就地反馈；复用单一 notification store，不新增第二套提示通道。

**可观察验收条件：**

- Toast 固定悬浮，不推动正文、不遮住主要操作，保留状态色、关闭按钮、正确 `aria-live`；不抢焦点。
- success/info 默认 10 秒，error 默认 20 秒；手动关闭立即清理。新消息替换旧消息时，旧 timer 只能按消息 id 清理自身，绝不能关闭新消息。
- 表示进行中的短时提示在对应操作成功、失败、失效或离开时结束；字段/候选/批量条目的关键错误和重试始终留在原位。

| 提示事件 | 生命周期 | 必须保留的其他反馈 |
| --- | --- | --- |
| 非关键成功/信息 | 10 秒或手动关闭 | 无需复制为页面错误 |
| 全局错误摘要 | 20 秒或手动关闭 | 字段/候选/条目错误与重试入口 |
| 新提示替换旧提示 | 新 id 独立计时 | 旧 timer 不得清掉新提示 |
| 加载结束/离开 | 立即结束对应 loading 提示 | 操作结果仍由就地状态表达 |

**定向验证：** notification store、`GlobalNotification` fake timers、`App` 受影响 Vitest，typecheck/lint；真实 Chromium 验证 10/20 秒、替换、手动关闭、布局不位移和键盘焦点不跳转。

**停止条件：** 任一关键恢复入口只能依赖 Toast、定时器无法按 id 隔离、或悬浮层遮挡确认主操作时停止并修复，不得以延长时间规避。

## 6. 实施顺序、协作与统一门禁

拟交 Luna 的顺序：WP-40-A → 独立审核/红测/集中修复/复审 → WP-41-A → WP-41-B → WP-41-C → WP-41-D → 统一独立审核与 Stage 41 Gate → WP-42-A → 最终独立审核。D0 是文档资产工作包，不运行浏览器；其余 UI 包均在各自完成时做定向真实 Chromium，完整门禁只在相应 Stage 收尾一轮。

每包开始前主 Agent 提供：仓库/分支、精确文件与问题、不可改范围、最小验证、停止条件。共享工作区同一时刻只允许一个写入者；开发 Luna 结束后才由独立审核者读取代码并形成一次完整问题清单，测试者先固化最小红测，再复用同一修复 Luna 集中收口，复审通过后才能进入下一包。

建议提示词摘要：开发 Luna——“仅实现当前 WP，遵守草案 CAS/安全边界，跑列明定向验证并在停止条件触发时停止”；测试——“将审核问题固化为最小红测，不放宽既有断言”；审核——“独立核对 AC、revision/幂等、敏感泄漏、业务失败与 HTTP 成功分离”；修复 Luna——“只收口已列问题及红测，不扩范围”。本轮实际协作模式：Terra 单 Agent 规划，未启动开发、测试、审核或修复 Agent。
