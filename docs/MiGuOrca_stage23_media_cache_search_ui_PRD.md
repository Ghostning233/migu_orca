## 2. 背景与问题

Stage 22 已完成单个/批量真实 MiKan 候选状态与显式选择链路，但人工验收仍发现以下可用性和性能问题：

1. 候选封面直接引用 MiKan 域名，客户端网络可能无法稳定访问，导致单个搜索和批量卡片长期显示“暂无封面”。
2. MiKan `/Home/Search?searchstr=...` 页面可能达到约 4 MiB，候选所需信息位于响应前部；当前 transport 仍持续读取后续无关内容，增加等待时间和流量。
3. 批量候选共享区仍占用 `#search-results-panel` 内部布局，容易引入嵌套滚动；期望改为锚定“查看候选”按钮的气泡式浮层。
4. DRAFT 卡片展开草案时，卡片内容把同一网格行其他卡片一起拉长；草案详情应统一进入现有“订阅方案详情”区域。
5. 结果卡片缺少“总集数/当前播出进度”的统一摘要。总集数只可使用 MiKan 明确公开的元数据；当前最新播出集数的数据来源尚未确定，本阶段只保留“待开发”占位。
6. 多处禁用按钮 hover 时仍出现等待光标或旋转效果，用户会误以为操作仍在加载。
7. fake 番名解析只覆盖少量开发示例，`无职转生s4` 等输入无法可靠转换为正式季度标题。该问题重要但不属于本阶段；Stage 24 后已登记为 BL-018，按 backlog 另行规划。

## 3. 目标

1. 在服务端建立安全、有限、可清理的 MiKan 封面缓存，并让 Web 页面只加载本地同源封面地址。
2. 图片请求与正文渲染解耦；页面先显示稳定占位，图片独立加载完成后展示，不阻塞其他内容。
3. 通过有测试证据的响应提前停止策略减少 MiKan 搜索页无用下载，同时保持候选结果完整。
4. 将批量候选改为锚定触发按钮的单实例浮层，支持切换、点击外部关闭、Escape 关闭和正确焦点管理。
5. 将批量草案内容统一展示到“订阅方案详情”，保持每张结果卡片高度与布局相互独立。
6. 在结果卡片展示紧凑的 `播出进度：待开发 / 总集数`；总集数未知时显示 `播出进度：待开发 / 未知`。
7. 统一禁用按钮视觉与鼠标行为，禁用状态不再冒充 loading。

## 4. 非目标

1. 不实现流式封面代理或渐进式字节转发；该可选方向记录为 `docs/optional_features.md` 的 OF-001。
2. 不实现“当前最新播出集数”的真实抓取、聚合或推断，只显示“待开发”；后续评估登记为 backlog BL-020。
3. 不实现正式番名/季数智能解析；该课题登记为 backlog BL-018，按后续优先级另行规划。
4. 不自动选择 MiKan 候选、自动接受草案或自动提交 Auto Bangumi。
5. 不新增后台常驻 worker、任务队列或定时守护进程。
6. 不允许任意 URL 图片代理，不让封面端点成为 SSRF 或开放代理。
7. 不把原始图片 URL、HTML、RSS、cookie、token、原始响应体或本地绝对缓存路径暴露到 storage、URL、日志、错误详情或测试 trace。

## 5. 产品与技术决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D23-01 | 封面缓存默认有效期 7 天 | 以最后一次成功访问时间计算滑动有效期；过期文件由安全的机会式清理删除。 |
| D23-02 | 封面下载总超时 10 秒 | 超时或失败不阻断候选/页面响应，继续显示占位。 |
| D23-03 | 单张封面上限 5 MiB | 只接受明确允许的图片 Content-Type 和实际图片内容，超限/非图片拒绝缓存。 |
| D23-04 | 缓存使用不可逆 key | 客户端只获得同源 `/api/v1/posters/<opaque-key>` 地址；不接受任意 URL 查询参数。 |
| D23-05 | 原子写入与机会式清理 | 下载完成并校验后原子替换缓存文件；请求期间做有节流的清理，不引入后台 worker。 |
| D23-06 | 浏览器异步图片加载 | 候选正文先渲染，图片使用占位、`loading="lazy"`、`decoding="async"`；图片失败不影响任何操作。 |
| D23-07 | 搜索提前停止必须以结构证据为准 | 不直接依赖固定“1000 行”；优先以稳定字节标记/候选区域完成条件停止，标记缺失时保留有界 fallback。 |
| D23-08 | 候选浮层全页单实例 | 同时最多一个浮层，锚定当前按钮；切换按钮即切换内容，点击外部或 Escape 关闭。 |
| D23-09 | 草案详情复用现有详情区 | 结果卡不再内嵌完整草案；“查看草案”把对应未保存预览送入统一详情区域。 |
| D23-10 | 使用“播出进度”文案 | 展示格式为 `播出进度：待开发 / 12 集`；总集数未知为 `播出进度：待开发 / 未知`。 |

## 6. 封面缓存契约

### 6.1 数据流

```text
MiKan 候选 parser 得到受信任公开 poster_url
  ↓
服务端按规范化 URL 计算 opaque key，并登记受限来源元数据
  ↓
API 对外只返回同源 poster cache URL
  ↓
浏览器先渲染候选正文与占位，独立请求本地 poster URL
  ↓
缓存命中：更新最后访问时间并返回图片
缓存未命中：10 秒内下载、限流读取、校验、原子写入后返回
失败：返回稳定占位/错误状态，不影响候选操作
```

### 6.2 安全边界

1. 只允许由 MiKan 候选 parser 产生并通过现有 HTTP(S)/host 规范化的图片来源。
2. 公共路由只接受固定格式 opaque key，不接受 `url=`、host、path 或重定向目标等用户输入。
3. 下载端拒绝非 HTTP(S)、跨越允许来源策略的重定向、私网/环回/本地地址和异常端口。
4. 文件名由哈希与白名单扩展名构成，缓存目录不可由请求参数控制；禁止路径穿越和符号链接逃逸。
5. 只缓存允许的图片 MIME，最多 5 MiB；下载失败、解码/校验失败或中断不得留下半文件。
6. API、日志和错误 details 不回显原始封面 URL、完整失败 URL或本地缓存路径。
7. 删除只作用于解析后的明确缓存目录和过期缓存文件，绝不递归删除宽泛目录。

## 7. MiKan 搜索响应提前停止

Stage 23 先用当前真实页面的脱敏 fixture 证明候选区域与停止标记关系，再修改 transport：

1. 记录完整响应与提前停止响应解析出的候选集合，标题、MiKan ID、封面 URL、顺序和去重结果必须一致。
2. 支持停止标记跨 chunk、UTF-8 字符跨 chunk、候选标签跨 chunk 和缺失标记。
3. 若稳定标记“搜索结果”确实位于所有候选数据之后，可在读取到该标记且已获得完整候选结构时停止；不能仅按字符串首次出现盲目截断。
4. 若页面结构证据不支持该标记，则采用经过测试的等价候选区域结束条件；固定 1000 行只能作为调查对照，不作为无证据生产规则。
5. 标记缺失或局部内容不足时回退现有有界读取，继续遵守最大响应、总流式时间和超时限制。
6. 测试记录完整 fixture 与提前停止的读取字节数，必须证明实际减少无用下载。

## 8. 批量审核 UI

1. FOUND 卡片的“查看候选”打开锚定按钮下方的浮层，浮层有气泡箭头指向当前触发按钮。
2. 浮层优先显示在按钮下方；空间不足时允许上翻或限制在 viewport 内，不创建结果 panel 的第二个内部滚动条。
3. 点击另一张卡片切换内容与锚点；点击浮层外空白、按 Escape、切换模式、重新搜索或删除 active 卡片时关闭。
4. 打开后焦点进入浮层首个有意义控件；关闭后焦点返回触发按钮。ARIA 使用 `aria-expanded`、`aria-controls` 和适合的 dialog/popover 语义。
5. 同时最多存在一个候选浮层；窄屏可退化为锚定卡片附近的全宽浮层，但不能溢出 viewport。
6. DRAFT/READY 卡片的“查看草案”不展开卡片内部内容，而是把该 preview/request 渲染到现有“订阅方案详情”区域并滚动/聚焦到详情标题。
7. 卡片网格每个 item 自身高度不受其他卡片详情内容影响；移除内嵌 `.batch-card-review` 后仍保留修改、保存、接受等现有详情动作。
8. 卡片新增单行 `播出进度：待开发 / <总集数或未知>`；不得用有效种子数推断当前播出集数或总集数。

## 9. 后续 handoff：正式番名与季数解析

后续专项必须解决以下问题，本阶段只记录并保持现有人工候选选择 fallback；由于 AutoBangumi 真实兼容问题优先级更高，该事项不再绑定 Stage 24：

1. `萌王S4` 等开发示例依赖 fake provider 特例，`无职转生s4` 等真实简称无法稳定映射为官方标题与第四季搜索词。
2. UI 中“源名称：搜索词：...”存在字段标签叠加，需要随正式解析契约一并收敛。
3. 需要定义可测试的季数解析、中日文/别名映射、数字与 `S4` 表达、多个搜索词生成、低置信度和无结果 fallback。
4. 无论解析质量如何，AI/规则只生成候选搜索词，不自动选择最终 MiKan 合集。

## 10. Ralph User Stories

### US-165：建立安全封面缓存契约与存储

作为部署者，我希望服务端安全缓存候选封面，从而避免客户端直接依赖 MiKan 图片域名。

验收标准：

1. 新增版本化封面缓存配置和 repository，默认 TTL 7 天、下载总超时 10 秒、单图上限 5 MiB。
2. 缓存 key 不可逆且文件名 path-safe；缓存目录由应用配置确定，任何请求参数都不能控制文件路径。
3. 缓存写入采用临时文件加原子替换；失败、中断、超限或非图片响应不留下半文件。
4. 机会式清理只删除明确缓存目录内超过 TTL 的普通缓存文件，并有节流避免每个请求全量扫描。
5. 单元测试覆盖命中、未命中、滑动续期、过期清理、路径穿越、符号链接、超限和原子写入失败。
6. Tests pass。
7. Typecheck passes。

### US-166：接入同源封面端点与异步图片加载

作为用户，我希望候选封面从 MiGuOrca 服务端加载，并且图片失败或变慢时不阻塞其他内容。

验收标准：

1. 候选响应对外提供同源 opaque poster URL，不把原始 MiKan poster URL 交给浏览器。
2. 封面端点只接受已登记的 opaque key，不接受任意 URL；阻止私网/环回/本地地址、异常重定向和开放代理行为。
3. 端点只返回白名单图片 Content-Type，缓存失败使用稳定占位/404 语义且不影响候选选择。
4. 单个和批量候选图片使用占位、`loading="lazy"`、`decoding="async"`，正文和操作先于图片可用。
5. 浏览器测试证明页面其他内容无需等待图片响应即可交互，图片完成后显示，失败后保持占位。
6. 新 API、日志、URL、storage 和 trace 不泄露原始图片 URL、缓存绝对路径或外部响应内容。
7. Verify in browser using dev-browser skill。
8. Tests pass。
9. Typecheck passes。
