## 2. 产品目标

把当前以工程对象和历史页面为中心的 SPA，重组为零技术基础番剧用户可以理解的四个入口：

```text
添加番剧 | 追番方案 | 追番管理 | 设置
```

核心用户旅程：

```text
输入名称
  → 选择真实 MiKan 合集
  → 审核并保存确认
  → 自动进入追番管理的待提交条目
  → 用户显式提交到 Auto Bangumi
  → 查看、修改、启停、刷新或删除外部订阅
```

单番是默认首页；批量是同一入口中的可切换模式。页面以“当前要做什么、发生了什么、下一步
是什么”为主，不要求用户理解 Request、draft、RSS、storage、API 或内部英文状态。

## 3. 目标与非目标

### 3.1 目标

1. 实现已冻结的四项导航、混合布局、状态语言和暖白/深海蓝/珊瑚橙视觉系统。
2. 单番只呈现“输入名称、选择合集、审核并保存确认”三步。
3. 批量支持 1、典型 12、最多 36 部，使用左卡右详情、异常优先和连续滚动。
4. 单番与批量使用同一详情编辑核心、同一 draft 状态和同一服务端重算结果。
5. 保存确认后自动切换追番管理并定位待提交项；外部提交必须再次由用户显式确认。
6. 追番方案承担本地方案查看、修改、复制再用与历史；追番管理承担外部状态和动作。
7. 对加载、空、无结果、过期、冲突、部分成功、提交失败、能力降级和人工恢复提供就地反馈。
8. 保持敏感信息只在当前页面组件内存，确保 DOM、URL、storage、日志、trace 和 sourcemap 无泄漏。
9. 每个切片同时完成 TypeScript、Vitest、真实 Chromium、键盘、读屏和目标桌面宽度验收。

### 3.2 非目标

1. 不更换 Vue 3、TypeScript、Vite、Vue Router、Pinia 或 OpenAPI 生成客户端。
2. 不做移动端产品布局；未来移动管理端另立 PRD。
3. 不在前端复制 MiKan、季数、字幕组、过滤、确认、复核或 capability 业务规则。
4. 不实现当前已更新集数，只显示统一的“待开发”能力状态。
5. 不持久化未保存的单番/批量现场；刷新或离开前明确警告，确认离开后不承诺恢复。
6. 不实现批量外部删除，不允许任何页面触发媒体文件删除。
7. 不直接消费 Auto Bangumi 原始响应，也不拼接未进入 OpenAPI 的临时接口。
8. 不在一个 PR 中重写所有页面、删除旧路由并同时修改后端领域规则。

## 4. 冻结的信息架构与路由

| 一级导航 | 目标路由 | 主要职责 |
| --- | --- | --- |
| 添加番剧 | `/app/add` | 单番默认入口、批量切换、候选选择、详情审核、保存确认 |
| 追番方案 | `/app/plans` | MiGuOrca 本地方案列表、详情、修改、复制再用、历史 |
| 追番管理 | `/app/tracking` | 待提交、提交/恢复、外部订阅列表与管理 |
| 设置 | `/app/settings` | 默认规则、storage profile、连接测试与诊断 |

兼容重定向：

| 旧路由 | 新路由 |
| --- | --- |
| `/app/workbench` | `/app/add` |
| `/app/requests` | `/app/plans`，保留公开 `request_id` query |
| `/app/queue` | `/app/tracking`，将可解析的公开上下文转换为 `tracking_id` 后定位 |

`/`、`/index` 目标改为 `/app/add`；`/Settings`、`/settings` 继续到 `/app/settings`。URL 只允许
公开、已保存的 `request_id`、`tracking_id` 和非敏感视图状态；搜索词、draft、candidate context、
批量输入、凭据、endpoint 和目录绝对路径不得进入 URL。

## 5. 应用壳层与视觉系统

1. 顶部导航高度、内容宽度、颜色、字号、间距、圆角、阴影、状态色和动效统一消费
   `frontend-ux-design-tokens-v1.md` 的语义 Token。
2. 当前导航同时使用文字语义、颜色和形状/下划线，提供 `aria-current="page"`。
3. 每个可见区域最多一个强主操作；危险操作只在二次确认弹窗的最终按钮使用危险色。
4. 全局只承载导航、非敏感连接摘要、加载提示、错误边界和通知；业务恢复动作留在相关页面。
5. Toast 只报告非关键完成结果，错误、部分成功、过期和恢复入口必须留在条目或详情附近。
6. 1280～1920 px 为产品桌面布局范围。200% 缩放属于桌面无障碍验收：可以把双栏临时纵向
   重排以保持控件可达，但这不是移动版，也不能隐藏主字段、主动作或只显示“请放大窗口”。
7. `prefers-reduced-motion` 取消分段位移、平滑滚动和非必要动画，保留即时选中和焦点反馈。

## 6. 状态所有权与共享组件

### 6.1 状态边界

| 状态 | 所有者 | 持久化 |
| --- | --- | --- |
| 单番/批量两份输入 | 添加番剧 route-local store | 否 |
| candidate context、draft ID、revision | 详情 draft store | 否 |
| 当前批量卡片、勾选、筛选、滚动位置 | 批量工作台 store | 否 |
| Auto Bangumi 凭据 | 追番管理页面局部 credential session | 否；离开/刷新清空 |
| Request、tracking、队列、capability | 服务端权威；前端只缓存公开 DTO | 否，重新读取 |
| 非敏感用户偏好 | 服务端；必要的相对 profile 可沿用现有安全策略 | 按现有契约 |

不得新增持久化 Pinia 插件。页面组件卸载时清除 draft、candidate 和凭据；离开保护只负责提醒，
不借机把现场写入 localStorage、sessionStorage 或 IndexedDB。

### 6.2 必须复用的领域组件

建议组件名可按实现调整，但职责必须唯一：

```text
AnimeModeSwitch          单番/批量分段控件
AnimeTitleInput          单行/自增高多行统一输入
CandidateCollectionList  真实 MiKan 合集选择
AnimeDraftEditor         单番和批量共享的详情编辑核心
SubtitleGroupSelect      字幕组选择和服务端重算状态
ResourceSummary          有效资源与总集数摘要
SafeInfoDialog           只消费 safe-info DTO 的全部信息弹窗
BatchReviewCard          批量摘要和字幕组快捷入口
TrackingInspector        追番动作与外部状态检查器
CredentialSessionDialog  当前页面内存凭据和连接引导
```

`BatchReviewCard` 和 `AnimeDraftEditor` 的字幕组必须绑定同一个 item draft store；快捷修改不能在
卡片中维护第二份值。服务端重算成功后，以同一原子响应更新字幕组、资源、计数、revision 和状态。

## 7. 页面规格

### 7.1 添加番剧：单番

1. 初始进入 `/app/add` 时默认选中单番，焦点在单行名称输入。
2. 首屏只突出名称输入、主按钮和三步预告；Auto Bangumi 未连接只显示轻量提醒，不阻止搜索。
3. 候选步骤只展示理解选择所需的标题、封面、季度证据和总集数；永不自动选中候选。
4. 季数冲突、证据不足或无结果在候选附近解释，并提供修改名称/季度或重新搜索。
5. 详情步骤展示标题、季度、选定合集、字幕组、有效资源、总集数和更新“待开发”；过滤、目录、
   RSS 摘要和诊断收进默认折叠的高级设置。
6. “全部信息”是独立按钮，打开只读弹窗；不与基本信息/字幕组做成编辑页签。
7. 唯一主操作为“保存并确认”。成功后 `router.replace` 到 `/app/tracking?tracking_id=...`，高亮
   新条目；此时尚未创建外部订阅。
8. 保存成功确认失败时保留已保存结果，显示“重试确认”，不要求重新搜索。

### 7.2 添加番剧：批量

1. 分段控件可点击、键盘激活并播放同一滑动动画；两种模式分别保留输入。
2. 批量输入每行一部，随内容自增高，达到上限后内部滚动；空行忽略，超过 36 部在本地立即
   阻止，同时仍依赖服务端校验。
3. 1 部时唯一卡片自动成为当前详情；12 部使用典型双栏；36 部仍连续滚动，不分页。
4. 左栏支持标题搜索、状态筛选、只看异常和下一异常；异常默认位于前部，但修复后不自动跳位。
5. 卡片展示封面、标题、季度、审核状态、字幕组、有效资源、已更新/总集数和必要操作。
6. 卡片选中只控制右侧详情；批量勾选是独立复选框，读屏和视觉上不能混淆。
7. 当前选中项被筛选隐藏时右侧继续显示，并提示“当前详情未在筛选结果中”；清除筛选后保持选择。
8. 固定操作栏持续显示已选、可确认、需核对、重算中和失败数量。阻断项不可勾选，并就地解释。
9. 批量保存确认允许部分成功：成功项从未保存工作台移出并进入待提交，失败项原位保留；焦点移到
   第一失败项，成功项不得再次提交。
10. 有未保存修改时，应用内导航使用自定义确认；浏览器刷新/关闭使用原生 `beforeunload`。确认离开
    后不承诺恢复。

### 7.3 追番方案

1. 使用较宽松的列表—详情结构，默认按最近修改排序，支持标题和状态筛选。
2. 列表只展示标题、季度、字幕组、方案状态、修改时间和追番状态链接，不混入外部运行按钮。
3. 详情复用 `AnimeDraftEditor` 的展示/编辑字段和 `SafeInfoDialog`，不复制另一套修改表单。
4. “复制再用”进入 `/app/add` 并以内存 handoff 创建新草案起点；若刷新，要求重新选择，不把
   candidate/draft 写入 URL。
5. 已进入追番流程的方案显示“前往追番管理”；外部启停、刷新、删除只在追番管理执行。

### 7.4 追番管理

1. 页面由状态总览、约 58%～64% 列表和 36%～42% sticky 检查器组成。
2. 列表是单选行，不显示复选框，不提供批量外部删除；当前行使用背景、边界/指示条和
   `aria-current` 的等价语义。
3. 初始可读取本地安全投影；用户提供临时凭据并“同步 Auto Bangumi”后才访问外部系统。
4. 凭据在该页面实例内可复用；离开 `/app/tracking`、刷新、取消或明确清除时立即销毁，不进入
   Pinia 持久化、URL、storage、通知、日志或错误 DOM。
5. 待提交项的检查器以“提交到 Auto Bangumi”为唯一强主操作。点击后显示影响说明并确认，
   服务端复核通过才外部写入。
6. 复核失败显示“尚未创建外部订阅”、问题列表和“返回修改方案”；深链到对应本地方案详情。
7. 超时结果未知显示“正在确认外部结果”，禁用再次创建；只允许查询/恢复同一幂等操作。
8. 已生效项按 capability 展示修改、启用/停用、刷新和删除；`UNKNOWN` 能力只读降级并允许重探测。
9. 删除确认必须逐项说明外部番剧/RSS/任务影响，并固定说明“保留 MiGuOrca 本地方案，不会删除
   已下载媒体文件”。最终请求只能调用 `delete-external`。
10. 外部孤立对象可显示为“仅存在于 Auto Bangumi”，但不能伪造本地方案或提供“返回编辑方案”。

### 7.5 设置

1. 使用分组卡片，只承载默认规则、相对 storage profile、qBittorrent/Auto Bangumi 连接测试和
   脱敏诊断。
2. 删除“默认保存订阅方案”偏好；普通流程固定使用“保存并确认”，不再要求用户预先理解保存策略。
3. 高级技术字段默认折叠，展开前使用用户语言说明用途；不把 Settings 变成业务提交入口。
4. 连接测试成功/失败都清除敏感字段；失败只显示固定中文恢复建议。
5. 恢复默认必须确认，失败时回到上次服务端成功值，不让客户端猜测最终配置。

## 8. API 依赖矩阵

| 前端切片 | 可复用当前 API | 必须等待的新后端能力 |
| --- | --- | --- |
| 应用壳层/Token | 无业务依赖 | 无，可先行 |
| 共享候选与详情 | MiKan candidates、Request preview | draft revision、safe-info |
| 单番添加 | 当前候选生成 | 单番 save-confirm、tracking 建立 |
| 批量审核 | batch parse、当前逐条基础 | 36 上限、revision、batch save-confirm |
| 追番方案 | Request list/detail/modify/history | safe-info、tracking 链接/状态 |
| 追番管理本地态 | 当前 Request/queue 可迁移 | tracking list/detail、复核、统一幂等提交 |
| 追番管理外部态 | 当前连接/创建基础 | capability、sync、管理 adapter、映射与动作 |
| 设置 | 当前 preferences/connections | capability 摘要；移除旧偏好契约（如存在） |

实现 Agent 不得用前端连续调用 `preview-save → accept` 代替 save-confirm，不得根据当前 queue
拼装永久 tracking 列表，也不得根据连接测试的单个 `submit_supported` 猜测完整管理能力。

## 10. PR 与回退边界

1. 每个实施包至少一个独立 PR；若超过约 8 个业务 story 或同时触碰 3 个以上 feature，可继续拆。
2. 一个 PR 不得同时新增后端端点、重写两个主要页面并删除旧实现。
3. F-A 保留旧客户端路由兼容重定向；每个新页面先通过功能对等和新增体验验收，再移除旧组件。
4. 新旧页面过渡期间只能共享 OpenAPI client 和服务端状态，不维护两套手写 DTO。
5. 删除旧 route/component 前提供引用搜索、bundle 结果、Chromium 旅程和回退说明。
6. 每个 PR 的描述必须列出设计偏差；无偏差也要明确写“无已知设计偏差”，不能静默改变规格。

## 11. 验收策略

### 11.1 单元与组件

- 模式切换分别保留输入，单番拒绝换行，批量自增高并校验 36 部。
- draft revision 乱序、重算中、失败、恢复上次一致值和卡片/详情同步。
- 筛选隐藏当前项、下一异常、勾选与当前详情选择相互独立。
- 部分成功 reducer 只移除成功项，失败项保持用户修改和焦点目标。
- capability `SUPPORTED/UNSUPPORTED/UNKNOWN` 对动作展示和禁用原因的稳定映射。
- 凭据组件在成功、取消、模式切换和卸载时清空，错误不得插入原始响应。

### 11.2 真实 Chromium

交互规格 AC-01～AC-25 全部必须映射到测试。至少覆盖：

1. 1280×720、1440×900、1920×1080；200% 缩放仍能到达所有字段和操作。
2. 仅键盘完成单番、批量、追番提交、弹窗与恢复；焦点在详情切换和错误后可预测。
3. 1、12、36 部连续滚动，无默认分页；选择、勾选、筛选和滚动上下文不丢。
4. 批量部分成功、提交前复核失败、超时未知、capability 探测失败和外部删除确认。
5. 页面刷新、浏览器后退、旧 URL 重定向和已保存公开 ID 深链。
6. `prefers-reduced-motion`、状态非仅颜色、读屏名称与适度 `aria-live`。
7. DOM、URL、local/session storage、IndexedDB、console、trace、截图名和 build sourcemap 的
   敏感值检查。

浏览器测试使用 route fake 或后端 fake transport，不访问真实 MiKan、Auto Bangumi 或
qBittorrent，不向真实外部实例执行写操作。

### 11.3 人工视觉验收

对照效果图只检查方向和层级，不做脆弱的逐像素复制：

- 单番首页留白、输入主次和三步预告；
- 批量 V2 的双栏比例、独立“全部信息”按钮和固定操作区；
- 追番管理 V2 的单选列表与检查器；
- 批量部分成功和提交前复核失败的就地恢复；
- Token、文字对比、焦点、长标题、无封面和真实中文换行。

## 13. Gate 4 进入条件

只有同时满足以下条件，才能把候选实施包转换为正式 Stage/Ralph stories：

1. 后端 B-A～B-D 的 Stage 边界、路由、DTO 和兼容策略已评审。
2. F-A～F-G 的负责范围、依赖和 PR 顺序已确认，没有一个 story 同时承担跨层大重写。
3. 所有 AC-01～AC-25 已映射到后端、Vitest、Chromium 或人工验收责任方。
4. 效果图与 Token 的已知生成偏差已经归零，文字规格优先级清楚。
5. 现有 Stage 27 功能对等测试有保留、迁移或替代清单。
6. 实现与验收由不同 Agent/会话承担；项目管理会话只维护 PRD、决策和验收结论。

## 14. 完成标准

1. 四项导航和所有目标页面按已冻结结构实现，旧路由安全迁移。
2. 单番三步、批量 1/12/36、保存确认、待提交、外部管理和恢复形成完整闭环。
3. 单番与批量共享详情核心，卡片/详情无重复状态源，后端业务规则没有复制到前端。
4. 所有异常状态、无障碍、桌面视口、200% 缩放和敏感值边界通过独立验收。
5. 每个切片可独立回退，最终发布不依赖未提交的 mock-only API 或临时手写 DTO。
6. Gate 5 验收通过后，才可宣布本轮前端体验重构完成。
