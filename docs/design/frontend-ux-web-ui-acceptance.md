# Web UI 视觉与交互验收标准

状态：2026-09-24 已确认的目标验收标准（#139），待在「添加番剧」页面率先实施，再用于后续 Web UI 工作。具体截图基准必须由用户在真实浏览器画面上审核通过后才能入库，不能把当前实现的截图直接晋升为基准。

## 1. 证据的先后关系

1. 已获批效果图决定视觉目标与信息层级；图像生成造成的文字错误、虚构数据和示意尺寸不是业务契约。
2. 把与目标冲突的 Token／页面数值基线逐项修订为可测的布局、样式和状态规则，不用旧基线为明显视觉偏差辩护。
3. 在隔离数据、固定浏览器环境中截取真实页面；用户逐状态审核通过后，才把截图定为视觉回归基准。更换基准同样需要说明差异并重新审核，不能仅靠更新截图让失败测试转绿。
4. 自动验收同时包含行为、几何和视觉回归。只产出像素差统计、只检查截图尺寸，或仅有绿 CI，均不构成视觉通过。

## 2. 固定测试条件与安全

- 主视觉画布为 1440×900；1280×800、1920×1080、200% 缩放检查布局与可用性。使用真实 Chromium、固定字体／设备缩放／浏览器版本、确定性文案与海报 fixture，等字体及图片加载完成后截图。
- 用 mock 的 MiKan、Auto Bangumi、qBittorrent 响应和隔离存储，绝不使用真实凭据、用户运行数据或真实外部写来制作基准截图。
- 动态或敏感区域不得靠大面积掩码掩盖差异；确需排除时逐块命名、写明原因并审核。海报优先采用固定安全 fixture。截图、diff、trace 不得含秘密、完整 RSS URL、magnet、本地绝对路径或未经审核的真实用户数据。
- 默认动效验收与 `prefers-reduced-motion` 验收分开：前者观察切屏过程与结束位置，后者允许立即定位，但均须保留焦点、键盘和读屏语义。

## 3. 添加番剧首轮验收矩阵

| 场景 | 必须验收的可观察结果 |
| --- | --- |
| 单番首屏 → 四候选工作台 | 搜索成功自动到工作台；一次向下手势完整停在工作台顶部，不能留在两屏中间；向上回首屏同理。 |
| 单番长候选／长草案 | 内容沿同一页面滚动轴连续展示，标题与返回按钮一起移动；一次手势刚到工作台顶部时停住，下一次向上手势才切回首屏；无候选列表／草案面板第二条滚动轴。 |
| 滚轮命中区 | `#app-main` 内容、内边距、大屏两侧留白都能驱动外层滚动；顶部导航可见；外层滚动条任何鼠标状态下均不可见，滚轮／触控板／键盘仍可用。 |
| 返回按钮 | 平滑回到首屏后再聚焦搜索框，不因聚焦瞬移；不清除未保存工作。 |
| 候选卡 1～4 项及状态变化 | 1280／1440／1920 正常桌面宽度 1～4 项同排居中，窄视口按 4→2→1 列切换、不出现 3+1；四卡主操作对齐；季数核对、加载和失败不拉长邻卡或让下方内容跳位。候选卡没有「高级信息」下拉框／浮层。 |
| 批量 1／12／36 部 | 搜索首屏与工作台整屏切换；左右栏各自内部滚动且栏内滚轮永不切屏；模块外空白区可以切屏，固定操作栏无遮挡。右栏合集候选卡采用横向封面／信息／按钮结构，1440×900 至少可见两张完整卡，没有小封面旁大片异常空白；当前合集加载态不改变卡片几何。 |
| 边界视口／缩放 | 1280×800、1920×1080、200% 缩放下没有横向溢出、不可滚动大片空白或关键控件遮挡；空间不足时优先完整可读。 |

每个改变布局的信息状态要有可复现 fixture、关键 DOM 几何断言和用户审核的真实浏览器截图。视觉基准以获批的渲染结果为准，设计位图仅负责引导；交互过程不能由静态截图替代，必须由浏览器动作断言。

## 4. 视觉回归门禁

- 只比较同一固定环境与同一业务 fixture 的基准／当前截图。任一 RGB 通道差值大于 12 计为显著差异像素；显著差异比例必须 **≤0.5%**，超出则自动测试失败。这个门槛在首张基准建立前已冻结，不能按每次 PR 的差异反向调宽。
- 具名、说明原因的动态区域排除面积合计 **≤5%**；不得排除导航、整张卡片、主按钮或其他关键交互区。优先固定测试数据与图片，而非使用掩码。
- 关键锚点、容器位置和尺寸偏差 **≤2 CSS px**；字体、颜色和控件状态另有数值／computed-style 断言。截图门禁不能替代交互、无障碍和业务状态检查。
- 首次批准截图前连续捕获并验证稳定性。如果噪声超过门槛，应固定字体、图片、动画或运行环境，不提高 0.5%／5%／2px 门槛来适配噪声。
- 视觉差异失败时先核对 fixture／字体／构建是否稳定，再由用户判断是代码修复还是目标设计变化。任何基准替换需与实现改动分开审阅；不得以整卡掩码或删除断言规避偏差。

现有 `tests/browser/visual_support.py` 仍指向已归档的六张旧效果图；旧用例的差异比例仅被打印，尚无硬阈值。因此它们不能作为本标准已落地的证据。
