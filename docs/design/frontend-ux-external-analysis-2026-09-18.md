4.2 所有用户故事共同遵守的要求

维度	验收要求
人工选择	搜索结果即使只有一项，也不能自动生成已选择的真实合集；批量自动“查看唯一条目”不等于自动选择合集

4.3 用户故事 US-01：清楚地开始单番搜索

目标： 用户进入页面后可以直接输入名称，并理解后续仍需选择合集和审核。

验收标准：

首页以“添加番剧”为唯一主标题，单番默认选中。
名称输入和搜索按钮组成直接关联的操作组；保留可见字段标签，不能只靠 placeholder。
三步预告为“输入名称 → 选择真实合集 → 审核并保存确认”。
初次进入不展示空结果大面板；无结果后的直连救援入口沿用现有能力与安全约束。
单番／批量切换保留各自原文和光标位置；不持久化到浏览器存储。
搜索成功进入候选阶段，输入收为搜索摘要，提供“修改搜索”。
状态	必须呈现	操作规则
初始／空白输入	标签、三步说明、不可搜索原因	不发送请求
输入有效	搜索主操作	允许搜索
搜索中	输入保留、文字加载；已有结果标为正在更新	防重复；旧结果不能冒充新结果
有候选	搜索摘要、候选区域	人工选择
无结果	无匹配说明、修改名称／搜索表达入口	可使用既有救援路径
失败	搜索区安全错误和重试	保留原文

失败与恢复： 网络、上游和内部错误按既有分类映射；不直接展示原文，也不把所有失败归因于 MiKan。

无障碍： 首次焦点落输入；模式切换支持键盘；搜索完成聚焦候选标题；校验失败定位字段。

桌面响应式： 宽桌面限制输入行长；1280 下搜索动作与错误仍就近；200% 缩放允许操作组换行。

验证建议： Vitest 验证输入保留和请求防重；契约测试复用现有搜索结果分支；Chromium 覆盖初始、空结果、失败及键盘搜索。

4.4 用户故事 US-02：比较候选并明确选择真实合集

目标： 用户通过标题、季度证据及总集数比较真实候选，并知道自己的选择是否正在处理。

验收标准：

候选优先展示安全封面、标题、季度证据、总集数与选择动作；没有封面用占位，不从其他候选猜配。
候选阶段不展示有效资源数、过滤结果或已更新集数推断。
单番候选采用便于比较的自适应布局，不固定要求三列；批量右栏使用紧凑候选布局。
点击后仅被点击候选显示加载文字；同一单番会话或同一批量条目的其他候选暂不可重复选择。
批量其他条目可继续查看或操作，不能全页锁定。
季度冲突就近提示；是否需要阻断确认沿用服务端判断，不能由前端从标题自行裁定。
状态	必须呈现	操作规则
候选可选	比较信息、选择按钮	等待人工选择
候选需核对	具体安全证据或缺失说明	允许按既有流程选择，审核阶段处理阻断
正在生成草案	点击处文字加载	同条目防重，其他条目不误锁
生成成功	当前条目进入审核	不自动勾选其他条目
生成失败	对应候选附近错误	可重试或改选
候选上下文失效	重新搜索／核对提示	不继续用失效上下文生成

失败与恢复： 普通生成失败保留候选与搜索词；过期按现有恢复语义清除失效能力。

无障碍： 每个选择按钮带候选名称；加载状态可读；成功后聚焦审核标题，失败保留操作上下文。

桌面响应式： 长标题可换行，按钮不可被挤出；候选少时不拉伸成低密度巨卡；减少动态效果时使用清楚的静态进行中反馈。

验证建议： Vitest 验证单番会话锁和批量 item 锁；契约测试核对候选／生成成功、失败、过期；Chromium 用 held route 验证当前候选加载及另一批量条目可操作。

4.5 用户故事 US-03：审核单番草案，并理解修改和最终确认

目标： 用户能同时理解选中的合集、筛选效果和当前确认条件。

验收标准：

默认顺序为“已选合集 → 字幕与筛选／资源结果 → 确认条件与保存”。
在空间足够时，编辑和资源结果相邻；不能为了双栏让字段或长标题过窄。
资源区展示契约提供的有效资源摘要和少量安全标题；“已排除数”仅在来源和统计口径明确时展示，不能随意相减推算。
完整资源默认折叠，字幕组为一级、资源标题为二级缩进；高级设置不重复展示默认层字段。
未保存阶段不新增 safe-info 调用；已有折叠信息必须逐字段核对安全投影，不能因名称叫“全部信息”就当作安全证明。
“保存修改”为次操作，无待提交修改时禁用；附近说明“仅更新本次草案”。
“保存并确认”放在审核内容之后，禁用状态和原因来自同一响应式状态。
本地保存成功后进入我的追番定位“待提交”，不创建外部订阅。

自动重算的冻结语义：

字幕组变更立即请求。
包含、排除、正则、大小写规则在最后一次变更后 1.5 秒提交。
目录名不自动提交；通过“保存修改”提交。
“保存修改”可立即提交尚未到期的待处理规则。
最终“保存并确认”不得隐式提交待编辑内容。
状态	资源与配置展示	保存修改	保存并确认／恢复
服务端一致、无待修改	当前已生效结果	禁用	无阻断则可用
防抖等待／目录待提交	上次已生效结果＋待处理标记	可提交	禁用，解释未生效修改
重算在途	上次结果标为正在更新	防重禁用	禁用
重算成功	配置、资源、状态、revision 原子更新	无待处理则禁用	按最新结果决定
确定可恢复失败	新输入标为未生效；保留上次一致结果	重试／恢复入口	恢复前禁用
新结果零资源／字段阻断	最新零资源或具体问题	允许适当修正	禁用并解释
revision 冲突／草案失效	不再呈现为可确认草案	不继续旧修改	按现有语义重选、重新生成
保存中／结果待确认	保留审核上下文和结果面板	锁定冲突写入	防重复，按既有契约恢复

高风险验收：

同一草案在途时不以同一 revision 发送第二个修改；继续输入保留为待处理意图。
成功后使用服务端返回的新 revision；不自行猜版本。
批量卡片快捷修改和详情修改消费同一条目状态。
切换条目时清理相应定时器，旧响应不能覆盖当前详情；不能通过简单丢弃响应掩盖原草案已被服务端修改的事实。
对“响应丢失、服务端可能已修改”的情况，不能仅在前端恢复旧值就宣称回到一致状态。恢复方式必须核对现有契约。
冲突后不自动换新 revision 重放用户旧修改。

失败与恢复： 普通失败、确定拒绝、冲突、草案过期和结果未知分别表达。不能把所有状态合并成一个“重试”按钮。

无障碍： 错误关联字段；重算不抢输入焦点；完成适度播报；折叠控件支持键盘；禁用原因可见。

桌面响应式： 1440 和宽桌面突出编辑与结果关联；1280 可调整内部分栏；200% 缩放纵向重排；确认动作不遮挡资源或错误。

验证建议： Vitest 覆盖防抖、flush、在途继续输入、revision 更新、恢复和冲突；契约测试覆盖 CAS、允许 patch、零资源及保存；Chromium 验证“修改 → 新 revision → 保存确认”的连续路径。

4.6 用户故事 US-04：输入批量名称并真实理解搜索等待

目标： 用户清楚批量容量、当前搜索阶段以及接下来仍需逐项选择合集。

验收标准：

多行输入、每行一部说明、有效行数及搜索按钮在同一区域。
有效行计数忽略纯空行及行首尾空白，但不重写输入框原文。
0 行不可搜索；1～36 行可搜索；超过 36 行明确阻断，不截断。
搜索按钮使用“搜索候选合集”等符合实际阶段的文案，不使用容易暗示已生成审核草案的名称。
搜索中保留原文，展示整体不定进度和请求中的名称数量；数量是提交规模，不是完成进度。
完成后展示逐项结果和汇总；首次搜索前不展示完整空工作台。
状态	必须呈现	恢复／下一步
无有效输入	输入说明、0/36	输入名称
1～36 行	有效行数、搜索动作	开始搜索
超限	实际数量及上限、字段错误	删除或拆分
搜索中	保留原文、整体进行中	防重复；不伪造逐项状态
返回全部／部分结果	完成后的逐项状态及汇总	进入批量审核
整体失败	输入区错误、重试	保留原文
带未保存工作重新搜索	明确重搜影响	用户确认后按既有流程重搜

失败与恢复： 单项搜索失败只能使用现有整批重新搜索路径；不能照图承诺该项独立重搜。已返回候选的生成失败可按候选重试。

无障碍： 计数与错误关联输入；不要每次击键重复播报长文本；完成后聚焦工作台标题。

桌面响应式： 输入自动增高至合理最大高度后内部滚动；1280×720 下容量说明、错误和搜索动作均可达。

验证建议： Vitest 覆盖 0/1/36/37 行、空行与原文保留；契约测试核对服务端上限及部分结果；Chromium 验证等待期间不出现假进度。

4.7 用户故事 US-05：在批量工作台中区分查看、处理和勾选

目标： 用户能够逐项审核，同时清楚哪些条目正在查看、哪些条目将参与统一确认。

验收标准：

左卡默认突出标题、状态、必要警告和下一步；候选来源、偏好命中等信息按需展开。
点击卡片主体只改变当前详情；复选框只改变确认集合，不隐式切换详情。
“正在查看”通过选中边界、背景和可访问语义表达；勾选使用独立复选框。
不可确认条目不能被新勾选，并提供原因和处理入口。
原已勾选条目在重算或变为阻断时保留勾选意图，但不计入可确认 N。
1 部自动查看唯一条目，不自动选择真实合集；12/36 部保持连续列表，不默认分页。
筛选不清除勾选；当前查看项被隐藏时，右栏保留并提示。
条目修复后不自动跳位；异常重排必须显式触发。
左卡字幕组快捷编辑与右栏保持同一状态源，并明确区分待生效选择与当前结果。
状态	右栏	勾选／动作
待选择合集	候选列表	不可确认
当前条目生成中	当前候选加载	锁本条，其他条目可操作
草案可审核	共享草案详情	无阻断后可勾选
重算／阻断	原结果＋状态，或最新阻断	保留原勾选意图，不计入 N
搜索失败	安全错误及现有处理方式	不提供不存在的单项重搜
当前项被筛选隐藏	保留当前详情并说明	提供清除筛选入口
筛选无匹配	筛选空态	不冒充整个批次为空

失败与恢复： 当前条目失败不清空其他条目；“下一异常”需先让目标可见，再滚动、选中和聚焦。

无障碍： 读屏能分别识别查看项与勾选项；卡片导航不拦截内部表单键盘操作；空格只在复选框焦点上切换勾选。

桌面响应式： 左栏参考既有 34%～38% 布局并结合最小／最大宽度；长标题换行，关键错误不靠悬停；200% 缩放允许上下排列。

验证建议： Vitest 验证查看与勾选独立、隐藏项保留、稳定排序和 N 变化；契约测试核对真实状态映射；Chromium 覆盖 1/12/36 项及长标题。

4.8 用户故事 US-06：确认勾选的本地方案，并处理部分成功

目标： 用户明确本次保存范围，并在部分成功或未知结果时继续处理，避免重复保存。

验收标准：

批量详情复用 US-03 的编辑核心，不另放批量主保存按钮。
固定操作栏显示批次总量、已勾选数、当前可确认数及需处理信息，以分组呈现替代连续长句。
主按钮 N＝已勾选且当前可确认的条目数，不等于当前可见数，也不等于所有可确认数。
N 为零时不可用且有原因；未勾选的异常不阻止已勾选正常项确认。
点击后固定本次提交集合，防重复；其他操作是否可继续依现有状态机，不能改变正在提交的范围。
按 results[] 解释逐项业务结果，HTTP 200 不代表全部成功。
成功项进入待提交并从待审核集合移出；失败项原位保留；不回滚成功项。
仅重提仍失败且当前可确认的项，不重提成功项。
有失败或未处理项则留在工作台；全部完成才跳我的追番。
确认处明确“仅保存本地方案，外部提交需在我的追番再次确认”。
状态	固定栏／页面反馈	后续行为
未勾选／N=0	已勾选与可确认计数、不可用原因	选择或处理条目
可确认	“保存并确认 N 部”	提交明确集合
保存中	常驻保存状态	防重复；无契约支持时不展示实时逐项进度
全部成功且无剩余	成功结果	跳转并定位待提交项
部分成功	成功／失败／未处理汇总	留在工作台，聚焦首个失败
确定失败	条目原因、修复／重试入口	保留草案和安全编辑
结果未知	“暂时无法确认保存结果”等就地说明	按现有幂等／恢复契约处理，不盲目新建重试
保存成功、确认失败	仅在契约明确区分时显示此状态	保留已保存对象，走受支持的确认恢复

失败与恢复：

保存确认的网络超时不能直接解释为未保存。
重放绑定、键有效期及服务重启后的恢复必须以当前契约为准，不能套用外部 Auto Bangumi 的恢复接口。
若当前契约无法识别“保存成功、确认失败”，不得凭旧交互规格增加一个虚假的“重试确认”动作。

无障碍： 部分成功后聚焦首个失败，无失败但有未处理时聚焦首个未处理；按钮名称包含数量；状态汇总适度播报。

桌面响应式： 底栏可换行或重排；正文预留相应高度；1280×720 和 200% 缩放下不遮住末项、错误或详情控件。

验证建议： Vitest 覆盖集合计算、部分成功、重试排除成功项和焦点；契约测试覆盖逐项结果、幂等及落盘失败；Chromium 验证混合结果后的完整处理路径。
