## 6. 稳定比较区域与命名掩码（每图）

### 6.1 基线形态决定像素门禁是否适用

| 形态 | 定义 | 像素门禁适用性 |
| --- | --- | --- |
| **A. 设计工具参考图** | 产品方提供与冻结 Token 数值一致的 `1440×900` 参考图 | 图 01、图 02 可启用（掩码见 6.2）；**图 03 因文字密度超过 35% 掩码上限，只做锚点 + computed style + 几何门禁**（见 6.4） |
| **B. 数值型正式测量基线** | 直接以本提案第 3～5 节的数值规范作为获批基线 | 数值基线没有唯一像素形态，因此三图的门禁均为**锚点 + computed style + 几何**，不启用像素层 |

两种形态都**不得用当前实现截图反写目标**（PRD 明令）。建议：图 01/02 采用形态 A 以取得像素证据，
图 03 采用「形态 A + 仅几何门禁」或直接采用形态 B。

### 6.2 掩码与理由（形态 A）

像素门禁比较**整页 `1440×900`**（区域 = 全画布，`region=(0,0,1440,900)`），差异像素比例 `<= 0.5%`。
掩码只用于排除**文字字形墨迹**（Token 字体栈在本机无 Inter，中文回退 Noto CJK，字形栅格化
不可跨环境预测）。掩码矩形一律**严格小于文本容器的边框盒**，或仅覆盖字形行带，因此：

- 容器盒的 x/y/宽/高由 **锚点层**断言（`<=2 CSS px`）；
- 行数、截断与换行由**几何层**断言（元素 `clientHeight` 与行数，不依赖像素）；
- 因此像素层排除字形**不掩盖**排版、换行或截断错误。

### 6.4 图 03 的文字密度问题与三条路径

即使收窄比较区域也仍然超限，实测：

- 右栏区 + 操作层 `region=(536,240,1408,876)`（872×636 = 554 592），掩码 417 312 → **75.25%** ❌
- 左栏区 `region=(32,240,512,818)`（480×578 = 277 440），掩码 215 040 → **77.51%** ❌

原因是图 03 的可用区域几乎被文本容器占满，而 35% 上限与「禁止整卡掩码」不允许把整栏排除。
请审批时择一：

1. **分栏独立比较**：左右栏各自独立计算 `<=0.5%`。实测两栏均超 35%，故需要同时放宽面积或
   改用路径 2/3，**本路径单独不可行**。
2. **只比较结构性稳定带**：把比较区域收窄为容器骨架（身份区边界、双栏分界、折叠区 summary
   行、操作层），掩码只覆盖这些带内字形，其余区域不参与比较。
3. **图 03 只做锚点 + computed style + 几何门禁，不做像素硬门禁**，直到有文字密度更低的新基线。

建议：**图 01/02 整页比较（形态 A）；图 03 采用路径 3（或形态 B）**。理由是审核页的价值集中在
身份/筛选/资源层级与业务状态可达性，且 Stage 46 裁决 3C 已确立「文字密集区域不做像素硬门禁」
的先例。此项未获批前，US-365 不启用像素硬阈值。

## 11b. 实现校正（2026-09-21，US-363）

US-363 实现时发现三处提案数值与冻结 Token 的既有实现不完全一致，按「Token 优先」原则以**实现事实**为准，
并把门禁从「绝对 y 坐标」改为**可测量关系**（容器盒 + 宽高 + 间距 + 居中），避免把字体度量写死：

| 项 | 提案值 | 实现事实 | 依据 |
| --- | --- | --- | --- |
| 搜索表单项高度 | 52px（只计控件盒） | **81px**（label 21 + `--space-2` 8 + 输入 52） | Token V1 §7.3「字段标签始终可见」 |
| 模式切换轨道 | 236×60 | **238×62**（含 1px 边框 ×2） | `--border-default` |
| 帮助文字高度 | 18px（12/1.5） | **22.4px**（14/1.6，沿用共享 `.field-help`） | `--font-size-sm` + `--line-height-body` |

因此英雄区内容块高度为 **421.4px**、垂直居中后内容顶为 **275.3px**（96 + (780 − 421.4) / 2）。
门禁断言内容（`tests/browser/stage47_single_home_baseline.py`）：

- `HOME_BOXES`：每个元素的批准宽高（容差 2 CSS px）；
- `HOME_CENTERED`：英雄区、标题、副标题、模式切换、表单、帮助、三步预告的水平中心 = 720；
- `HOME_SPACING`：`title→subtitle 8`、`subtitle→mode 24`、`mode→form 32`、`form→help 16`、`help→steps 40`；
- 垂直居中：容器上下留白相等（±2 px）。

同时把「点击搜索后英雄区必须留在原位」写入实现：`showSingleHome` 用 `!hasResults`（而不是 `!searchStarted`），
英雄区在搜索中仅取消垂直居中（`.is-searching`），保证输入与主按钮不因状态切换而改变几何。
