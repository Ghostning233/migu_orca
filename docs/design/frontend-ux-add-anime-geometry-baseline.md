## 1. 两屏结构与滚动

| 量 | 值（1440×900） | 来源 |
| --- | --- | --- |
| 顶栏 | `y 0..72` | `--size-shell-header` |
| 滚动接收区 | 覆盖整个浏览器视口，包括 `#app-main` 内容、内边距及大屏两侧留白；顶部导航保持可见 | 已确认的空白区滚动要求 |
| 两屏切换 | 首屏一次向下滚动完整、平滑地到工作台顶部；工作台内容滚到顶部后，再向上滚动完整、平滑地回首屏；不中途停在分界处 | 已确认的切屏语义；减少动态效果时允许立即定位 |
| 滚动所有权 | 单番候选与草案内容共用页面滚动，不另设内部纵向滚动；批量工作台屏固定为一屏，左右栏保留各自内部滚动，栏内滚轮不触发切屏 | 已确认的模式差异 |
| 切屏判定 | 由 `useAddAnimeScreenScroll` 的纯决策函数判定：首屏向下手势 → 完整到工作台顶部；工作台顶部向上手势且本次手势未滚动过内容 → 回首屏；同一次手势刚到顶 → 停住 | 手势边界可单测，不靠 CSS 文本 |
| 滚动条 | 添加番剧页面的外层滚动条与批量双栏的内部滚动条都不可见（`scrollbar-width: none`，且不占滚动条槽），但滚轮、触控板、键盘与读屏导航能力保留 | #145 已确认目标；#148 落地，不以隐藏滚动能力换取外观 |
| 连续手势边界 | 一次手势把长工作台滚到顶部时停在顶部；仅下一次向上手势切回首屏 | 避免浏览工作台标题时意外跨屏 |
| 搜索首屏 | 720px 宽居中（`x 360..1080`），内容在屏内垂直居中 | Stage 47 获批页面专属宽度 |
| 候选工作台屏 | 内容宽 1376、至少高 780；超出一屏的内容在同一页面滚动轴上继续展示，标题与返回按钮随内容滚动 | 不用内部滚动框裁切卡片 |

成功后自动滚到第二屏并把键盘焦点移到结果标题（`#candidate-search-heading`，`tabindex="-1"`）；
「返回搜索首屏」（`#mikan-back-to-search`，高 44）平滑定位完成后再聚焦输入，**不清空**下方未保存的候选；聚焦不得造成瞬移。
失败与无候选都留在首屏：就地反馈 + 一个 44px 的次级动作（重试／重新搜索），直连救援入口默认收起。
缩减动态效果下滚动行为为 `auto`。

## 2. 候选行（1～4 项同排居中）

| 量 | 值 | 来源 |
| --- | --- | --- |
| 卡片宽 | 由可用宽度与获批视觉比例决定，不将旧 `332px` 设为产品要求；同一行同宽，尺寸须整体协调。1440 实测 `331px = (1376 − 3×16) / 4 − 1`（1px 余量避免亚像素舍入把第四张挤到第二行） | 旧值只是 #110 的 1440 实现基线 |
| 卡片间距 | `--space-4` 16px | Token |
| 行对齐 | 1～4 项在常规桌面宽度均为一行、居中、同宽；宽度不足时直接切为每行 2 项，极窄视口再切为每行 1 项，**禁止 3+1** | 已确认的 4→2→1 列规则 |
| 卡片布局 | 竖排：封面在上，标题/证据/主操作在下 | 设计图 02 |
| 同排稳定性 | 四卡同排时卡片与主操作保持对齐（`align-items: stretch` + 主按钮 `margin-top: auto`）；季数核对、草案生成中及生成失败等短状态落在预留的两行反馈区（`min-height: 14px × 1.5 × 2`），因此不拉长邻卡、不使下方内容跳位。200% 缩放空间不足时优先完整可读，允许自然增高 | 已确认的状态切换验收 |
| 封面 | 随卡片可用宽度缩放，保持横向比例；最终尺寸以获批浏览器截图与新数值测量锁定 | 不沿用旧 300px 固定宽度 |
| 主操作 | 「选择此合集」占满卡片内容宽 | 设计图 02 |
| 数量上限 | 最多渲染 4 项；超出只显示前 4 项 + 简短截断提示 | 用户故事 10 |
| 窄视口 | 用容器查询按候选区实际可用宽度判定：≥1001px 四列、≥561px 两列、更窄单列；不横向溢出，也不出现 3+1 | 200% 缩放可达性 |
| 候选诊断信息 | 单番与批量候选卡均移除「高级信息」入口，不设置替代浮层；保留底层候选字段与页面既有搜索诊断，但不为未来用途预留卡片控件 | 取代旧 F4/Stage 43 的卡片按需展开要求；合集编号和匹配搜索词不是当前选合集所需证据 |

1280／1440／1920 桌面档均须支持四张卡同排。四卡在 1280 档应自适应缩窄，而不是让第四张落到第二行；
具体卡宽随首张获批浏览器截图测量后冻结，不从旧 332px 倒推目标。

## 4. 批量首屏与逐部进度（Issue 112）

| 量 | 值 | 来源 |
| --- | --- | --- |
| 进度分段 | 每部一段，`flex: 1 1 --space-3`、高 `--space-2`、`--radius-pill` | Token |
| 已完成段 | `--color-primary` 底 | Token |
| 未完成段 | `--color-surface-subtle` 底 + `--color-border` 边 | Token |
| 进度文本 | 「正在逐部搜索：已完成 X / N 部」，`role="status"`、`aria-live="polite"` | 可访问状态 |
| 续接说明 | 「进度只保留在当前页面：刷新或关闭后需要重新搜索；服务端请求不因此被取消。」 | Issue 112 AC4 |

进度只由服务端逐部完成事件推进（FOUND／EMPTY／FAILED 都算完成），不做时间估算；
搜索期间停留在批量首屏且不出现可审核条目，整批拿到稳定结果后才把工作台带入视野并移焦点。
契约形态：同一 `POST /api/v1/batches/parse` 在 `Accept: text/event-stream` 时返回
`item`／`result`／`error` 事件；没有持久任务、取消或续接入口。
