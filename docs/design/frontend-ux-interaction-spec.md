本文是效果图、前端实现、后端契约补齐和独立验收的共同交互依据。本文不决定颜色、字体、阴影、插画等视觉风格，不猜测现有 API 路由或字段名，也不授权全面前端开发。

### 1.1 已冻结边界

以下事项已经确认，不在实现或验收阶段重新讨论：

1. 应用使用顶部一级导航，固定为“添加番剧 / 我的追番 / 设置”。
2. 添加番剧默认进入单番搜索；单番和批量使用同一输入组件，以滑动分段控件切换，并分别保留输入。
3. 单番用户可见流程严格为三步：“输入名称 → 选择真实 MiKan 合集 → 审核并保存确认”。外部提交不属于第四步，只能在我的追番中由用户显式执行。
4. 批量审核使用左侧卡片列表、右侧共享详情和固定操作栏；详情编辑核心与单番复用。
5. 批量按 1 / 12 / 36 部设计，不默认分页，不默认虚拟滚动。
6. 批量保存并确认采用逐条部分成功：成功条目进入待提交，失败条目原位保留，不回滚整批。
7. 外部提交前由服务端复核方案、候选和必要上下文；失效时阻断并要求重新确认。
8. 本轮不提供服务端批量工作会话。未保存的批量现场刷新后不可恢复，只提供离开与刷新警告。
9. 删除 Auto Bangumi 外部订阅保留 MiGuOrca 本地方案和历史，且永远不删除已下载媒体文件。
10. 没有可靠数据时，总集数与“已更新集数”都显示“未开发”（能力尚未实现的固定占位），不得从种子、RSS、有效资源数或下载数量推算（Issue #131/#165）。
11. 未连接 Auto Bangumi 不阻止搜索、合集选择、本地方案编辑和保存；进入我的追番或实际提交时才升级为阻断。
12. AB 凭据仅保存在部署端专用私有配置，跨页/刷新/重启保留；设置页仅编辑本次输入。秘密不进入
    URL、浏览器持久化存储、公开 DTO、业务状态或日志；配置更换不能重绑旧未知操作。
13. “全部信息”只展示服务端公开白名单中的安全字段，不展示凭据、敏感 endpoint、完整 RSS URL、magnet、原始外部响应或本地绝对路径。

## 2. 全局壳层与通用交互

### 2.1 顶部导航

1. 顶部导航在三个一级页面持续可见。当前页同时使用文字/形状选中态和可编程的当前页语义，不只靠颜色。
2. 导航右侧显示“未配置 / 已配置 / 连接可用 / 需检查”。不展示 endpoint、账号、版本或秘密；
   激活状态入口进入设置连接区域，不打开全局凭据弹窗。连接可用仅表示当前配置最近探测通过。
3. “我的追番”可显示待提交与失败条目的合计徽标；为零时隐藏，徽标具有可读名称。
4. 点击品牌返回添加番剧首页。若当前存在未保存工作，仍须先经过离开保护。
5. 一级页面切换完成后，焦点移动到新页面主标题；通过保存成功、处理失败等上下文跳转时，优先移动到目标条目。

### 2.2 反馈层级

| 层级 | 使用场景 | 规则 |
| --- | --- | --- |
| 字段提示 | 输入校验、季度或过滤规则错误 | 紧邻字段，说明如何修复，不只改变边框颜色 |
| 条目提示 | 重算、保存、提交、刷新等单条错误 | 保留在对应卡片/列表行/详情，提供重试或处理入口 |
| 页面提示 | 连接异常、能力降级、部分成功汇总 | 保留到用户处理或主动关闭 |
| Toast | 非关键完成反馈 | 不抢焦点，不作为错误的唯一载体 |
| 模态阻断 | 离开未保存工作、连接要求、危险操作 | 焦点限制在弹窗内，必须显式选择后继续 |

加载时保留已有内容并标记“正在更新”，不得用整页空白替换可用数据。每个列表都必须有说明原因和下一步动作的空状态。

### 2.3 焦点和弹窗

1. 所有可操作控件显示清晰焦点环，焦点顺序与视觉阅读顺序一致。
2. 打开弹窗时记录触发控件，焦点移入弹窗并在其中循环；Escape 关闭可取消的弹窗；关闭后焦点回到触发控件。
3. 列表项被移除时，焦点移动到下一条；没有下一条则移动到上一条或列表标题，不能落到页面根节点。
4. 自动定位只移动视口和焦点，不自动触发确认、提交、启停或删除。

### 2.4 离开保护

存在未保存的单番草案、批量候选/编辑或勾选集合时：

- 点击一级导航或其他应用内链接：阻止跳转，提示“本次审核尚未保存，离开后需要重新搜索”，默认焦点放在“留在此页”。
- 刷新、关闭标签页或外部导航：触发浏览器原生离开警告。
- 用户确认离开后：清除未保存现场和临时凭据，不创建服务端恢复会话。
- 已经保存确认的方案不触发警告；正在执行的写操作不可通过普通导航中断，界面先说明其状态。

## 3. 添加番剧首页与单番三步

### 3.1 首页和模式切换

1. 首页默认选中“单番搜索”，首屏只突出一个搜索主操作，并以简短文案预告三步流程。
2. 分段控件包含“单番搜索 / 批量搜索”。点击标签、方向键移动并用 Enter/空格激活时使用同一状态切换；选中项具有 `aria-selected` 等价语义。
3. 单番输入限制为一行；批量输入允许换行，随内容自动增高，到达设计最大高度后在输入框内部滚动。
4. 两种模式保存各自的内存输入。切到另一模式不会清空或截断内容；再次切回时恢复原文本和光标位置。
5. `prefers-reduced-motion` 开启时取消滑块位移动画，以即时状态切换替代。

### 3.2 第一步：输入名称

1. 默认焦点位于单番输入框。空白或只含空格时搜索按钮不可用，并提供就地说明。
2. 触发搜索后，按钮进入加载态并防止重复请求；输入和已有结果保留，结果区标记“正在更新”。
3. 搜索成功后，输入区折叠为含搜索词和“修改搜索”的摘要，进入第二步并将焦点移到候选区域标题或第一张候选。
4. 无结果时在结果区显示“未找到匹配合集”，提供“修改名称”和“补充/修正季度”入口；不静默回到首页。
5. 网络或服务错误显示在搜索区域，保留输入并提供重试。

### 3.3 第二步：选择真实 MiKan 合集

1. 每张候选展示封面、标题、季度证据、总集数（无可信数据时显示“未开发”）和选择操作。候选阶段尚未
   生成 Request，不展示或猜测有效资源数；选择真实合集并生成草案后，才在第三步展示资源摘要。
2. 用户必须人工选择真实合集，不得以最高分候选自动越过本步。
3. 季数或标题证据存在冲突的候选标记“需核对”，仍允许选择，但进入第三步后必须明确处理阻断项才能确认。
4. 选择候选后生成审核草案并进入第三步；生成失败时错误留在该候选附近，其他候选仍可选择。
5. “修改搜索”返回第一步并保留搜索词；重新搜索会替换旧候选，若已有未保存编辑则先提示影响。

### 3.4 第三步：审核并保存确认

详情核心默认展示：封面、标题、季度、真实 MiKan 合集、字幕组、有效资源数、资源摘要、更新“未开发”/总集数，以及“全部信息”入口。过滤规则、目录、RSS 摘要和诊断信息放入默认折叠的高级设置。

1. “重新选择合集”返回第二步并保留搜索结果；当前草案有修改时说明返回会舍弃哪些修改。
2. 季数冲突、无有效资源、字段校验失败或字幕组正在重算时，“保存并确认”不可用，并在按钮附近列出阻断原因。
3. 触发“保存并确认”后锁定当前方案的写操作，服务端以组合行为完成校验、持久化和接受。
4. 成功：跳转我的追番，定位、高亮并聚焦新条目，用户可见状态为“待提交”；不创建外部订阅。
5. 保存成功而确认失败：保留已保存结果和用户选择，显示“重试确认”，不得要求重新搜索。
6. 请求失败或校验失败：保留草案，错误定位到相关字段或主操作附近，可修复后重试。

## 4. 批量输入与容量行为

### 4.1 批量输入

1. 每个非空行视为一个名称，解析前忽略纯空行和首尾空白，不改写用户输入框中的原文。
2. 有效行数超过 36 时禁止开始搜索，显示当前数量和上限，并请用户删除或拆分；不得静默丢弃超出条目。
3. 解析期间保留输入和逐条进度。单条解析失败不使整批失败；完成后进入双栏工作台并汇总成功、需核对和失败数量。

### 4.2 1 / 12 / 36 部

| 规模 | 行为 |
| --- | --- |
| 1 部 | 自动选中唯一卡片并显示右侧详情；左栏保持标准宽度，单卡不拉伸填满列表 |
| 约 12 部 | 左栏连续滚动，同屏可浏览数张紧凑卡片；右侧持续可见 |
| 36 部 | 显示标题搜索、状态筛选、只看异常和下一异常；固定操作栏始终可见；不分页 |

虚拟滚动只有性能验证证明必要时才可引入。若引入，筛选、选中、勾选、焦点和滚动恢复语义必须与普通列表一致。

## 5. 批量工作台组件

### 5.1 审核卡片

卡片只展示当前判断所需字段：封面、标题、季度、审核状态、字幕组下拉、有效资源数、更新“未开发”/季度总集数和主要操作。标题、季度、过滤、目录和资源预览等主要编辑在右侧详情完成。

卡片至少支持以下状态：解析中、正常、需核对季数、无有效资源、重算中、保存中、保存失败、已保存。状态同时使用图标/文字和可编程语义，不只靠颜色。

### 5.2 选中与勾选

1. 选中是单选，表示右侧正在查看哪一张卡；勾选是多选，表示哪些条目参加本次保存并确认。两者必须有不同控件和视觉状态。
2. 点击卡片主体改变选中并替换右侧详情；操作复选框只改变勾选，不隐式切换详情。
3. 正常、已完成所有核对且不在重算中的条目可勾选。阻断项不可勾选，并给出原因和“打开详情处理”入口。
4. “全选正常项”只作用于可确认条目，不选择异常、重算或失败项；筛选隐藏的条目是否被全选必须在控件文案中明确，默认只作用于当前可见结果。

### 5.3 右侧共享详情

1. 批量和单番复用同一详情编辑核心；卡片和详情读取、写入同一个条目草案。
2. 在卡片修改字幕组后，详情字段立即显示相同选择；在详情修改后卡片立即同步。服务端重算结果一次性更新两处。
3. 切换选中卡片直接替换详情，不复制第二套状态；列表滚动时详情保持可见。
4. 详情切换期间显示局部骨架或“加载中”，不得闪现上一条目的字段与新标题组合。

### 5.4 固定操作栏

操作栏持续显示：批次总数、已勾选数、当前可确认数、需处理数、重算中数和保存失败数；提供“下一异常项”和“保存并确认 N 部”。

1. N 只计算已勾选且当前可确认的条目。重算或变为异常的条目暂不计入 N，但保留其勾选意图并说明原因。
2. N 为零时主按钮不可用；存在其他异常不阻止确认正常条目。
3. 保存进行中防止重复触发，并显示逐条完成进度。
4. 操作栏不遮挡列表末项或详情底部控件；键盘能到达全部操作。

## 6. 排序、筛选、滚动与键盘

### 6.1 稳定审核顺序

1. 初次完成解析时，阻断性异常在前、其他需核对项其次、正常项在后；同组保持输入顺序。
2. 列表渲染后冻结当前审核顺序。条目修复为正常时只更新状态和计数，不立即跳到列表其他位置，以免丢失焦点和上下文。
3. 可提供显式“重新按异常排序”；执行后保持当前选中条目可见并恢复焦点。

### 6.2 筛选与搜索

1. 状态筛选、只看异常和标题搜索可以叠加，只改变可见性，不删除数据或清除勾选。
2. 顶部状态总数始终反映完整批次；同时显示当前筛选结果数量。
3. 清除筛选后恢复稳定顺序，以及该筛选条件下先前记录的滚动位置。
4. 当前选中项被筛选隐藏时，右侧仍显示该项，并提示“当前条目不在筛选结果中”，提供“清除筛选查看”；不得暗中切换详情。

### 6.3 下一异常与键盘

1. “下一异常项”从当前选中位置查找下一条未解决异常，到末尾后循环；没有异常时不可用并说明。
2. 若目标被筛选隐藏，系统先提示并临时显示目标，再滚动、选中并聚焦该卡；不能只移动焦点到不可见元素。
3. 卡片列表支持方向键移动选中项；Enter 激活卡片主要操作；空格只在焦点位于复选框时切换勾选，避免与页面滚动冲突。
4. Tab / Shift+Tab 按视觉顺序经过筛选、卡片内控件、详情字段和固定操作栏。列表自动滚动只保证焦点项可见，不重置用户滚动位置。

## 7. 字幕组重算与并发

1. 每个条目维护单调递增的 revision 或等价版本。每次修改字幕组或影响资源的规则时，使用新 revision 请求服务端重算。
2. 请求发出后，卡片和详情立即同步用户选择，该条目标记“重算中”，锁定其确认/勾选资格；其他条目继续可编辑和确认。
3. 只有响应 revision 等于该条目当前 revision 时才能应用；旧响应必须丢弃。若服务端会写入草案，也必须拒绝旧 revision 覆盖最新状态，不能只靠前端隐藏旧结果。
4. 成功时将字幕组、有效资源数、资源集合和审核状态作为一个原子结果更新，禁止出现“新字幕组 + 旧资源”的中间组合。
5. 失败时保留用户刚选择但尚未生效的字幕组，并明确标记“重算失败”；资源摘要继续显示为
   “上次有效结果”，不得把它与新字幕组组合成已生效状态。提供“重试”和“恢复上次有效值”；
   选择恢复后才整体回到最后一个服务端确认的一致状态，不得影响其他字段或其他条目。
6. 最新结果为零资源时转为“无有效资源”阻断态，提供修改字幕组/过滤规则入口，不得把旧资源继续显示为有效。

## 8. 批量逐条部分成功

1. 批量保存对每个可确认勾选项独立返回结果。
2. 成功项标记为“待提交”，从待审核集合中移出并计入汇总；失败项保持原位置、选择和非敏感编辑，显示可理解的原因与重试入口。
3. 完成后显示成功数、失败数和未处理数，焦点移动到第一个失败条目；若没有失败，移动到第一个未处理条目。
4. 若所选条目全部成功且工作台没有其他未保存条目，跳转到我的追番并定位本次新条目；若仍有失败或未处理项，留在工作台，不强制跳转，并提供“查看已成功条目”。
5. 重试只提交仍失败且当前可确认的条目；已成功项不得重复保存或创建第二份方案。

## 10. 我的追番

### 10.1 页面结构与能力

页面由状态总览、追番列表和右侧追番详情组成。状态总览固定覆盖待提交、追番中、已停用、已加入下载和需处理，计数取自服务端权威投影，并可作为筛选；处理中是行内临时状态，不单独成类。追番详情直接展示常用信息，操作记录与技术诊断默认折叠。

Auto Bangumi 3.1.18 是首个完整适配基线：目标能力包含已有番剧和 RSS 的列表、详情、修改、启用/停用、删除和手动刷新。设置页连接测试只用于诊断；实际提交、修改、启停、刷新和删除都在服务端同一次请求中验证已保存配置、连接、认证、精确支持版本与写能力，并在不满足时 fail closed。页面按服务端动作投影展示操作，未知动作或状态一律 fail closed。

### 10.2 显式提交

1. “待提交”条目提供固定文案的“提交方案”，点击后打开三按钮弹窗（取消 / 下载现有资源 /
   持续追番）并显示本次选择的作用范围；打开弹窗本身不产生请求，初始焦点在取消，选择后立即
   开始且不再有第二次确认。批量模式同理，一次批量只使用一个提交方式。
2. 已保存 Auto Bangumi 连接即可发起；服务端在同一请求内执行提交前检查，并展示将创建/改变的外部对象摘要，再由用户最终确认。
3. 确认后先由服务端复核。通过才发起外部写操作；失效则标记“需重新确认”，说明原因并深链回对应详情。
4. 提交中禁用重复提交。网络超时但结果待确认时显示“正在确认外部结果”，先按幂等键查询/重试，不立即再次创建。
   结果待确认的持续追番提交只提供两条只读或显式确认的路径（issue #183/#184）：只读“重新检查”用原
   operation 绑定的已保存连接核对，已确认存在即收敛且外部写入为零；仍待确认时给出已证实原因与具体
   重复/资源风险，用户再次确认后才以新 operation 重发（见 [ADR-0002](../adr/0002-risk-confirmed-manual-resubmission.md)）。
   主动重发不是原请求的安全重试，取消不产生任何外部写入，也不提供批量强制重发。
5. 成功转为“追番中”；失败保留本地方案和待提交上下文，就地显示原因。“下载现有资源”失败只提示“提交失败，可重新提交”（至少一次语义，不承诺安全重试），接受后进入“已加入下载”。

### 10.3 运行操作

1. 编辑：仅在 capability 支持时展示；保存前说明修改的是 Auto Bangumi 实际订阅，并在成功后刷新检查器。
2. 手动刷新：只刷新目标订阅/RSS 的外部状态，不改写本地方案；进行中防重复，失败可重试。
3. 暂停/恢复：影响外部订阅启用状态，不删除本地方案；成功后状态在列表、总览和检查器同步更新。
4. 删除：放在检查器或“更多操作”，必须经过危险操作弹窗。成功后外部对象消失，本地方案保留并变为未关联/未提交的可理解状态；媒体文件不受影响。
5. 所有操作按条目隔离错误。一个订阅失败不得使整个管理页不可用。

## 11. 设置

设置使用分组卡片，且不执行具体订阅提交：

1. Auto Bangumi 连接：完整输入并显式保存到部署端，显示安全摘要、测试已保存连接、更换与清除配置。
   保存不自动探测/同步/提交，不回显地址、账号或已保存秘密；修改需重新完整输入。
2. 默认字幕偏好：编辑常用字幕组优先级；保存后的新草案使用新默认值，既有方案不被静默改写。
3. 默认过滤规则：编辑默认包含/排除规则，明确影响范围并进行字段校验。
4. 存储与目录：展示安全的相对目录/分类摘要；不在普通页面显示本地绝对路径。
5. 高级与诊断：展示脱敏日志、版本与 capability 摘要，可进入二级区域。
6. 不再显示“默认保存订阅方案”偏好；普通流程始终使用“保存并确认”。
7. 删除 qB 连接测试及其独立接入。MiKan 搜索由服务端封装，用户只输入番名并选真实合集，
   不配置 MiKan 服务根、超时或凭据；可选合集直连只作为默认折叠的救援入口。

## 12. 连接、全部信息与危险操作弹窗

### 12.1 连接配置与引导

1. 顶部连接入口或追番页“去设置连接”进入设置，遵守已有离开保护；不新增全局凭据弹窗，
   返回业务页仍由用户再次明确确认动作，配置保存或探测不自动提交。
2. 使用“填写连接 → 保存配置 → 测试连接”的简短说明，不展示 Request、storage、API 等内部术语。
3. 保存失败保留本次受控输入并就地说明；成功保存、取消、切模式或离页销毁浏览器输入。
   测试已保存配置失败不删除部署配置，成功后显示安全能力摘要；已配置不等于在线。
4. 凭据唯一允许在专用部署配置中持久化；不回读或复制到其他 DOM、URL、浏览器 storage、业务状态、
   日志、错误或遥测。部署端配置只有用户明确清除才删除秘密。

本次连接/设置新目标及后端约束以[Stage 39 PRD](../MiGuOrca_stage39_deployment_settings_PRD.md)为准。
其余已完成 Stage 的效果图与历史验收保留，不因规格更新宣称新目标已交付。

### 12.2 全部信息弹窗

1. 是只读悬浮窗，内容超高时内部滚动，不复制编辑表单。
2. 只展示服务端白名单：标题、季度、合集安全标识、字幕组、过滤摘要、资源统计、季数证据摘要和脱敏历史。
3. 禁止展示或在 DOM 属性中携带凭据、敏感 endpoint、完整 RSS URL、magnet、原始外部响应或本地绝对路径。
4. 加载失败留在弹窗内并可重试；关闭后焦点回到“全部信息”按钮。

### 12.3 删除等危险操作

1. 标题和确认按钮必须写明对象与范围，不使用模糊的“确定”。
2. 删除外部订阅的文案明确：“删除 Auto Bangumi 中的订阅并保留 MiGuOrca 本地方案；不会删除已下载媒体文件。”如会连带外部 RSS/任务，须逐项列明。
3. 默认焦点在取消；确认后按钮进入进行态并防重复。失败保持弹窗或回到检查器就地提示，不改变本地方案状态。

## 13. 加载、空、错误、过期与恢复

1. 首次列表加载使用保持布局的骨架；局部更新保留旧内容并标记“正在更新”。
2. 搜索无结果、方案为空、待提交为空、外部订阅为空、筛选无匹配分别使用不同空态，并给最直接下一步。
3. 字段错误就近显示；单条业务错误留在条目；连接或页面级错误使用可恢复页面提示；未知错误不显示原始响应或堆栈。
4. 草案/候选过期时保留可安全保留的输入和用户偏好，清除失效上下文，说明为何需要重新搜索/核对。不得自动用旧上下文提交。
5. 保存成功确认失败提供“重试确认”；提交失败提供幂等重试；部分成功保留失败项；能力探测失败提供重试和只读降级。

## 14. 页面跳转与定位

1. 保存并确认成功：进入我的追番，定位、高亮、聚焦“待提交”条目，不自动提交。
2. 提交前复核失效：从我的追番深链回可编辑详情，并定位到需修复字段。
3. 保存并确认番剧后直接进入“我的追番”并定位新条目。
4. 深链目标不存在、已删除或当前版本不可管理时，降级到目标页面默认列表，显示“未找到目标条目”及可操作的返回/搜索入口，不出现空白页。
5. URL 只允许使用经安全评估、不可反推出敏感信息的公开标识。凭据、candidate context、未保存 draft 标识和完整外部 endpoint 不得进入 URL。

## 16. 无障碍与缩减动画

1. 使用语义化导航、主内容、列表、表单、状态和对话框结构；标签与错误信息正确关联。
2. 读屏必须能区分“当前详情选中项”和“批量勾选项”，并读出条目名称、状态和阻断原因。
3. 状态变化、重算完成、批量计数变化使用适度的 `aria-live` 播报；阻断错误及时播报，但连续进度不刷屏。
4. 所有状态使用文字或图标补充，颜色不是唯一信息来源；正文、控件、焦点满足通用对比要求。

## 17. 安全边界

1. 服务端白名单是“全部信息”的唯一事实来源；前端隐藏字段不是安全边界。
2. 敏感信息不得进入 DOM 隐藏属性、URL、localStorage、sessionStorage、IndexedDB、持久化 Pinia、日志、错误详情、截图或测试 trace。
3. 前端不缓存原始外部响应；诊断只使用后端脱敏 DTO。
4. 外部删除永不触发下载器的媒体删除能力；本地方案和审计历史保持可追溯。
5. 本轮继续以桌面 local-only 为前提。未来远程管理涉及的认证、授权、HTTPS、设备配对和公网暴露必须独立设计。

## 18. API / 后端行为需求

以下只描述前端依赖的行为，不断言现有端点已经具备，也不规定具体路由：

1. 组合保存确认：一次请求完成校验、持久化与接受；若持久化成功而接受失败，返回可定位的已保存结果和可重试状态。
2. 批量逐条结果：一一返回每条成功/失败、公开标识和安全错误原因；单条失败不回滚成功项。
3. 重算并发保护：请求和响应携带 revision 或等价版本；若重算会写草案，服务端拒绝旧版本覆盖最新版本；结果原子包含字幕组、资源和审核状态。
4. 提交前复核：验证本地方案、候选、字幕组/过滤结果、外部连接和必要上下文，返回结构化失效原因与“需重新确认”状态。
5. 外部写入幂等：提交、重试和结果查询使用稳定幂等标识；超时后能区分“未执行 / 执行中 / 已成功 / 已失败”，避免重复创建。
6. capability 探测：返回 Auto Bangumi 版本和逐项能力；以 3.1.18 为完整适配验收基线，其他版本只开放已确认能力。
7. 版本化严格 DTO：外部数据先映射到 MiGuOrca 的稳定安全 DTO，不能直接把版本相关响应交给 UI。
8. 外部 ID 映射：本地方案与 Auto Bangumi 番剧/RSS 对象建立稳定映射，支持定位、幂等、刷新、启停和删除后保留本地历史。
9. 全部信息白名单：提供专用只读安全视图，默认拒绝未列入白名单的字段。
10. 删除边界：删除外部订阅可明确报告连带删除的外部 RSS/任务；强制保留本地方案，且没有删除媒体文件的选项或副作用。
11. 脱敏错误：业务错误可操作且不含 endpoint、凭据、原始外部响应、绝对路径或堆栈。
12. 无批量恢复会话：本轮不为未保存批量现场提供持久化或跨刷新恢复；后端不应让前端误判其可恢复。

### 18.1 当前契约复核与缺口分类

本节用于防止实现阶段把目标能力误认为现成功能。复核基线为 2026-09-07 的当前代码与
`docs/api/openapi.json`；“部分基础”表示可以复用已有领域控制器，但仍需要新增或扩展正式契约。

| 需求 | 当前基础 | 实现结论 |
| --- | --- | --- |
| 单番组合保存确认 | 当前只有一次性 `preview-save` 和后续 `accept` 两个请求 | 全新组合端点；还需修正当前先消费 draft、后落盘导致保存失败无法重试的问题 |
| 批量组合保存确认 | 已有批量 accept 的逐条部分成功、幂等接受和队列能力，但只接收已保存 `request_id` | 部分基础；新增从未保存 draft 到保存、确认、入队的批量组合契约，复用现有逐条结果模型 |
| 字幕组/规则重算 | `preview-modify` 已能在服务端权威 draft 上重算并回写同一 `draft_id` | 部分基础；新增 revision/乐观并发，服务端拒绝乱序旧写，不能只靠前端丢弃响应 |
| 批量 36 部上限 | 当前 batch parse 接受任意非空行，未定义 36 部契约上限 | 新增前后端一致校验和结构化错误；不得只在 UI 截断 |
| 提交前复核 | 单番/批量当前会重新读取 Request 并检查 `ACCEPTED`，批量还具备逐条失败 | 部分基础；扩展为已确认字段、有效资源、外部连接/capability 和必要时效条件的结构化复核 |
| 外部写入可靠性 | 批量已有 `SUBMITTING` 先落盘、结果保存、重试和人工恢复；单番提交较弱 | 部分基础；统一单番/批量可靠性，并增加稳定幂等标识和结果确认，不能把超时直接当作未创建 |
| capability 探测 | 连接测试只返回版本、adapter 和 `submit_supported` | 扩展为列表、详情、修改、启停、删除、刷新等逐项能力及“探测失败”状态 |
| 版本化管理 DTO | Request、候选和现有结果已有严格 DTO/脱敏基础 | Auto Bangumi 管理为全新 DTO 与 adapter；禁止把上游响应直接交给前端 |
| 外部对象 ID 映射 | 提交结果可选保存 `ab_subscription_id`，3.1.18 成功时可能没有 ID | 全新稳定映射/对账能力；不得仅按标题猜测同一订阅 |
| 全部信息白名单 | 当前 Request detail 返回的范围大于本弹窗允许范围，并可能包含完整 RSS URL | 新增专用安全视图或更窄 DTO；前端隐藏字段不能替代服务端白名单 |
| Auto Bangumi 管理与删除 | 当前仅登录、状态探测和创建订阅；本地 Request 删除不是外部删除 | 全新版本化管理 adapter；外部删除必须强制保留本地方案与媒体文件 |
| 脱敏错误 | Flask 错误封装、提交结果和连接测试已有脱敏基础 | 复用并扩展到新端点，新增 fixture 与泄漏回归测试 |
| 无服务端批量恢复会话 | 当前批量卡片本就不跨刷新持久化，队列只在确认后建立 | 保持现状并补离开保护；不得为了恢复而持久化 candidate context、draft 或凭据 |

以上缺口必须进入后续后端支撑 PRD 和 OpenAPI 变更。视觉稿可以使用目标状态，但前端实现不得
在契约落地前用客户端拼接、推测上游字段或连续请求伪装原子操作。
