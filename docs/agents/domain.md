# 领域文档

本文件规定工程技能探索代码库时如何读取仓库的领域文档。

## 开始探索前

按需读取：

- 仓库根目录的 `CONTEXT.md`；或者
- 如果根目录存在 `CONTEXT-MAP.md`，读取它指向且与当前任务相关的 `CONTEXT.md`；
- `docs/adr/` 中与当前工作区域相关的 ADR。

如果这些文件不存在，静默继续，不将缺失本身报告为问题，也不预先建议创建。

`domain-modeling` 技能会在领域术语或架构决策真正得到确认时按需创建这些文件。

## 文件布局

本仓库采用 single-context 布局：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用 glossary 中的词汇

当 issue 标题、重构提案、假设或测试名称涉及领域概念时，使用 `CONTEXT.md` 定义的正式术语，不要改用其中明确排除的同义词。

如果所需概念尚未出现在 glossary 中，应先判断：

- 是否正在引入项目并不使用的新说法；如果是，重新考虑命名；
- 是否确实存在领域模型缺口；如果是，记录下来并交由 `domain-modeling` 处理。

## 标出与 ADR 的冲突

如果拟议方案与已有 ADR 冲突，必须明确指出，而不是静默覆盖。例如：

> 与 ADR-0007 的既有决定冲突，但值得重新讨论，因为……
