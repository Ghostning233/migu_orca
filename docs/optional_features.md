# MiGuOrca 后期可选功能

本文件记录已讨论但当前 Stage 不实施的可选能力。条目不等于承诺排期；进入开发前必须单独评估安全边界、维护成本和可验证收益。

## OF-001：流式封面代理与渐进显示

### 背景

Stage 23 采用“服务端完整下载、校验、原子写入缓存后返回”的稳定方案。浏览器通过同源图片端点异步加载，正文不等待图片，但首次缓存未命中时不会由 MiGuOrca 主动把未完成图片流转发给客户端。

部分 JPEG/图片格式支持浏览器在收到部分字节时从上到下或逐步清晰地显示。未来可评估由服务端一边读取受信任 MiKan 图片，一边转发给客户端，并在后台完成缓存。

### 可选目标

1. 首次缓存未命中时尽早向浏览器返回可显示字节，改善慢链路感知速度。
2. 同时把完整且校验通过的响应原子写入本地缓存，后续请求直接命中。
3. 对不支持渐进显示的格式自动退化为普通异步图片加载。

### 必须先解决的问题

1. 流式响应开始后，Content-Type、大小上限、解码有效性和上游中断更难在返回前完整校验。
2. 不得把部分文件或损坏内容写入正式缓存；需要临时文件、校验完成和原子晋升。
3. 客户端断开时需要正确取消上游读取并清理临时文件。
4. 多个客户端同时请求同一未缓存图片时，需要 single-flight/锁避免重复下载。
5. 仍需保持 10 秒总超时、5 MiB 上限、允许来源、重定向限制、SSRF 防护和日志脱敏。
6. 必须用真实浏览器证明首屏感知改善，并比较普通原子缓存方案的复杂度、故障率和资源消耗。

### 当前决策

暂不实施。只有在 Stage 23 普通异步缓存完成后，真实慢网测试仍证明首次封面体验明显不足，才考虑独立 Stage。
