# Stage 39 过渡开发流程

本文记录 2026-09-14 确认的 Stage 39 后半程临时流程。目标是保留 Ralph 已建立的验收边界，
同时避免逐 story 新进程反复读取同一背景。它只适用于 Stage 39；阶段完成后根据实际数据讨论
下一套正式工作流，不自动删除 Ralph skill、脚本或历史状态。

## 模型与角色

- 新主会话默认使用 gpt-5.6-terra medium，负责范围冻结、提示词、协调、关键复跑和最终结论。
- 持久开发 Agent 使用 gpt-5.6-luna，默认从干净上下文创建；普通实现不使用 Sol。
- Sol 仅用于大范围方向、跨模块高风险架构/安全争议，或 Terra 无法收敛的关键裁决。
- 测试与修复优先 Luna；独立审核按风险使用 Terra。一个共享工作区同时只有一个写入者。

推理档位不能解决长输入重复问题。主 Agent 应保持交接短小，按文件和 acceptance criteria 定向读取，
不把完整聊天、历史 progress 或无关工具输出复制给子 Agent。

## 干净且持久的 Luna 会话

持久开发会话由主 Agent 作为子 Agent 管理，但不继承主会话：

1. 使用 `fork_turns="none"` 创建 Luna 子 Agent；无特殊、可说明的依赖时严禁 `all`。
2. 首次提示词必须自包含：仓库与分支、HEAD、工作包 stories、目标/非目标、必读文件、写入范围、
   每 story 提交要求、验证层级和最终停止条件。
3. 同一 Agent 在一个工作包内连续开发；需要分回合时使用 follow-up 唤醒同一身份，不创建替代 Agent。
4. Agent 可一次读取共享设计和代码；仍须按依赖逐 story 满足 AC、更新 passes/progress 并精确提交，
   但不在每个 story 后等待用户或重新启动 `ralph.sh`。
5. 工作包结束后停止写入，交回主 Agent 和独立审核；未经用户继续指令不进入下一工作包。

主 Agent 身份不能在同一线程内真正转让给子 Agent。需要降低主上下文时，由旧主会话写交接文件，
用户新建 Terra Medium 会话作为新主 Agent；新会话只读交接、当前 PRD、最近 progress 和目标规范。

共享 OpenAPI/generated、fixture 和浏览器门禁在工作包合适的原子切换点集中执行。

## 开发、审核与修复

工作包开始前，主 Agent 先生成 AC—代码—测试矩阵并冻结非目标。开发 Agent 连续实现包内 stories，
每条只跑定向测试，包末统一跑共享门禁。独立审核只在工作包完成后进行一次，必须一次性覆盖全部 AC，
形成固定的问题清单，而不是边修边追加零散意见。

有阻断时按以下顺序收口：

1. 测试 Agent 只把固定问题清单转成真实最小红测，不修改业务代码。
2. 一个修复 Agent 按红测和清单集中修复，不扩大范围。
3. 主 Agent 复跑关键命令，独立审核给最终结论。
4. 若仍有阻断，继续复用同一修复 Agent 和剩余清单；不重启完整开发流程，不换 Agent 重读背景。

时间或 token 数值只作诊断阈值，不是中途停止条件。超过预期时停止新增 Agent、扩展范围和重复全量检查，
但必须把当前 story/原子切换完成到一致、可审核、可提交的状态；随后在边界生成交接或切换新主会话。

## 批次交付声明

每个工作包结束必须报告：

- 主 Agent、开发、测试、审核、修复分别使用的模型与推理档位；未使用的角色也说明。
- 是否全部通过干净上下文创建；任何非 `fork_turns="none"` 的例外及原因。
- 分别用一句话概括给各子 Agent 的提示词，不粘贴完整提示词或主会话历史。
- 完成 stories、提交、实际验证、剩余风险，以及未执行的完整/浏览器/真实上游检查。
- 明确停在工作包边界，未经用户授权不自动进入下一包、不 push/PR/merge。
