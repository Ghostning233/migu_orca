## Terra 制定 PRD 时必须核实

1. 先执行根 `AGENTS.md` 的仓库/分支/工作区检查，保留当前未提交的设计文档与图片；按需读 `frontend/AGENTS.md`、现行交互规格、设计 Token、OpenAPI 以及受影响代码和测试。不要把本交接当作当前执行 PRD。
2. 把每个工作包拆成可独立验收的故事、状态矩阵、依赖、非目标和最小验证命令；区分搜索中、候选生成中、草案重算中、可确认、阻断、失败及批量部分成功。错误处理须区分 HTTP 成功与业务失败。
3. 在 PRD 中澄清“保存修改”是立即提交待处理输入和未自动更新的高级字段，还是另有受契约支持的语义；核对未保存草案能否使用安全“全部信息”能力，以及批量失败的局部重试能力。若契约不支持效果图中的细节，明确降级或提出单独后端依赖，不凭图造接口。
4. 守住服务端草案权威、人工选择真实 MiKan 合集、方案确认与 Auto Bangumi 外部提交分离、敏感数据白名单，以及“已更新集数：待开发”。不增加数据库、后台 worker、伪实时进度或移动端范围。
5. 规定实施期的定向 Vitest/契约测试、`dev-browser` 真实 Chromium 场景和独立审核闭环；文案变化同时搜索旧断言。文档整理只做文档检查；完整门禁按执行 PRD 的收尾规则安排，不逐故事重复。
