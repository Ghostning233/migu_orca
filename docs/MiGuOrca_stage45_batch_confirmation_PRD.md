## 1. 目标与范围

本阶段收口批量审核工作台的三层体验：紧凑列表中“查看”与“勾选待确认”分离；固定操作栏清楚区分 N 部确认与完整批次确认全部；保存结果按服务端 `results[]` 展示恢复路径，并在全部完成时进入追番管理。

范围仅限前端既有批量审核旅程及其定向测试。服务端草案仍是权威：前端只消费 `draft_id + revision`，保留 scheduler、1.5 秒防抖、flush、save-confirm、CAS、unknown 恢复、safe-info 边界和本地/外部两次确认。

不新增 API、OpenAPI、生成字段、后端、持久化、外部写、未保存 safe-info、单项重搜、实时进度、分页或默认虚拟滚动；不重做 Toast timer/store，不改 D-03/Stage 44 已完成行为，也不把已保存模式的 `AnimeDraftEditor`、人工保存或其调用者回归降级。

## 3. 工作包与验收

### WP-45-A / US-355：紧凑列表与查看、勾选分离

作为批量审核用户，我希望快速定位待处理项，并清楚区分右栏正在查看的条目与将要保存确认的集合。

- 默认左卡突出标题、中文状态、阻断/错误与下一步；别名、偏好等辅助信息按需展开，紧凑不隐藏失败、未生效、unknown 或恢复动作。
- 卡片查看只改变右栏，复选框只改变“勾选待确认”集合；快捷字幕组编辑和右栏使用同源状态。修复不自动跳位，只有显式排序才重排。
- 筛选保留数据与勾选；当前详情被隐藏仍保留右栏和可达的清除筛选入口；筛选无匹配不能冒充批次为空。
- 下一个异常先清除/调整筛选使其可见，再定位、查看与聚焦。支持连续 1、12、36 项列表，不增加分页或默认虚拟滚动；1440×900 的 12 项普通短标题夹具至少同屏三张完整卡，长错误自然增长。
- 待选合集不可勾选确认；重算/阻断的已勾选项保留意图但排除资格并说明；删除临时卡后焦点落下一项、上一项或列表标题。读屏可区分查看/勾选，内部表单不被卡片快捷键截获，焦点环不裁剪。
- 用受影响 Vitest、批量视图/DTO/CAS 契约分支和真实 Chromium 验证 1/12/36、三视口、200%、长标题、键盘、焦点、reduced-motion、敏感 canary；不改接口与后端。

### WP-45-B / US-356：固定操作栏与两种确认范围

作为批量确认用户，我希望在点击前和二次确认时都准确知道本次仅在本地保存哪些方案。

- N 部为强主操作；“保存并确认全部”是持续可见的次操作，不能藏入更多菜单。完整批次、当前可见、已勾选/可确认和需处理计数分组呈现，并标明作用域。
- 可见全选只改变当前可见的勾选；N 采用 D-02 的完整手工勾选且有资格集合；全部复用 Stage 43 的完整批次资格。两入口的按钮状态、数量、安全标题清单、描述符和 `item_ids` 必须同源。
- 弹窗明确隐藏参与、排除项及“仅保存本地方案、外部提交仍须在追番管理再次确认”。打开弹窗后资格、`draft_id`、revision 或批次绑定变化均须零请求并要求重新确认；发送后由既有操作冻结意图，后续筛选不得改写它。
- 无勾选、勾选项均阻断、全批无资格、保存中和待核验均有常驻、可见的禁用原因，不能只依赖 `title`。unknown 恢复继续使用原冻结 body/key/revision/集合，不新起意图。
- 固定栏按实际多行高度预留滚动空间，最后卡片、字段和错误不被遮挡；模态、下拉与 Toast 层级正确，trap/Escape/关闭焦点恢复沿用 `ConfirmDialog`，缩放下背景不可交互。
- 先以最小红测固化 D-02 的隐藏手工项范围和版本变化拒绝，再做受影响 Vitest、真实 Chromium route mock/held route、契约回归与 canary；不修改保存协调器、API 或外部写。

### WP-45-C / US-357：部分成功、unknown 与完成导航

作为批量审核用户，我希望识别成功和剩余工作，并能安全恢复或在真正完成后进入追番管理。

- 以服务端 `results[]` 判定业务结果；常驻汇总同时说明本次结果与完整批次剩余工作，不能只发 Toast。成功项退出可确认集合，保留待提交/管理入口，不重复保存或回滚成功。
- 确定失败、失效、已保存待确认、unknown 和畸形 HTTP 200 分别走既有恢复。unknown 保持原 body/key/revision/集合；失败重试排除成功项；不得部分应用后宣称完成。
- 首个失败被隐藏时先可见化再聚焦；无失败但有未处理项留页并定位首项。全部成功且无剩余时按 D-04 自动进入追番管理；定位与导航只用真实公开 tracking 标识，不能伪造关联。
- 结果摘要只播报一次，焦点按失败、未处理、完成目标处理，不落在隐藏或已销毁节点。确认与未定位恢复仍分开。
- 用最小红测、受影响 Vitest、批量结果/DTO/CAS 契约和真实 Chromium 验证部分成功、held unknown、无失败有剩余、全成功导航、三视口、200%、长标题、键盘、焦点、reduced-motion 与 canary；不新增保存协调器或外部写能力。

## 4. 执行顺序、审核与验证

严格按 US-355 → US-356 → US-357。每包由唯一写入开发 Agent 完成后，主 Agent 独立审核，测试 Agent 先固化审核问题的最小红测，再由同一修复 Agent 集中修复并复审；前包闭环前不进入下一包。开发 Agent 首选 Claude Fable；环境不可用时如实记录 Luna 替代。

普通 story 仅跑受影响的 Vitest、typecheck、lint、build、`api:check`、views/DTO/CAS 契约和 `dev-browser` skill 所要求的真实 Chromium。浏览器一律使用 route mock、held route 与临时存储，禁止真实 MiKan/Auto Bangumi/外部写；检查敏感值不进入 DOM、URL、storage、trace 或截图。Stage 收尾才执行一次完整后端、前端和 Chromium 门禁。

每条 AC 有实际证据前不得设 `passes=true`。progress 记录实际命令、结果、提交、协作模型和剩余风险。提交只精确暂存本 story 文件，格式 `feat: [US-ID] - 标题`；不运行 `ralph.sh`，不 `git add .`。本 PRD不授予 push、PR、合并、强推、删分支或外部协调权限。

## 5. 阶段收尾门禁与停止条件

US-357 的审核/红测/修复/复审闭环后，隔离运行数据并一次性执行完整后端、前端与真实 Chromium 门禁；核对 OpenAPI 生成源/产物/调用者未漂移，`git diff --check` 通过，所有 AC 和 progress 证据可追溯。任一失败、敏感泄漏、CAS/unknown 语义漂移、固定栏遮挡或导航错误均停止收尾并回到同一修复 Agent，不以部分结果发布。
