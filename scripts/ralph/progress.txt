## Codebase Patterns

- Batch items use `item_id` as identity; input order, frozen review order, current detail, and selection are independent state.
- Route-local draft capabilities, revisions, idempotency keys, candidate context, and unsaved edits stay in memory and must not enter browser storage, URLs, logs, or traces.
- Frontend state cores are API-free and extract request/result types from `frontend/src/api/generated/api.ts`; transport hosts attach generated API calls later.
- User-facing status/error text is safe fixed Chinese copy; only stable error types and explicitly allowlisted public recovery fields may cross the UI boundary.
- `AnimeDraftEditor`/`useDraftSession` remains the shared draft editing core for single and batch flows; do not create parallel form state.
- Stage 36 batch save-confirm replaces the legacy preview-save → accept path incrementally; successful items consume draft capabilities and save keys, while unknown responses retain keys for explicit retry.
- Batch review layout keeps the card list and current-item detail in one responsive grid; card-body activation and checkbox activation must stop propagation so current-detail selection and batch selection remain independent.
- Keyboard navigation should operate on derived visible cards, while exception targeting may temporarily add a filtered card; focus restoration must use reduced-motion-safe scrolling and remain safe in jsdom.
