## Codebase Patterns
- Stage 1 through Stage 8 are complete; archived Ralph records live under `scripts/ralph/archive/`.
- Stage 9 Ralph work uses branch `agent/stage9-browser-automation`; US-063 complete, US-064–US-069 pending.
- Use `uv run pytest` and `uv run python -m compileall -q src` for project quality checks; bare `pytest`/`python` may not be on PATH.
- Preserve the existing top-level CLI JSON result envelope and do not change the current `migu-orca` command behavior while adding browser automation.
- Default CLI and Web UI Request generation must remain offline and fixture-backed unless the user explicitly opts into real external integrations.
- Default generation must not write local storage unless the caller explicitly opts into persistence through `--save-request` or the Web API `save_request=true` contract.
- Browser automation for Stage 9 must use local fixture data and temporary storage; it must not access real MiKan, Auto Bangumi, or qBittorrent.
- Browser automation artifacts, failure logs, screenshots, traces, UI text, API responses, docs, and fixtures must not expose raw HTML, raw RSS XML, complete endpoint URLs, cookies, tokens, absolute local paths, or other sensitive config values.
- Flask Web UI follows `/home/ghostning/github/user_level_flask` for structure: `src/apps/base.py:create_app`, `src/apps/registry.py:ALL_BLUEPRINTS`, module Blueprints, `extensions/flask_api` style response helpers, class-based `GetView`/`PostView`, Pydantic validators, `src/wsgi.py`, and Flask test client coverage.
- Flask blueprints should be exposed as per-module `blueprints` lists and registered centrally through `apps.registry.ALL_BLUEPRINTS`.
- Health endpoints return the target JSON envelope directly: `{ok: true, result: "ok"}`; Web JSON APIs should use `extensions.flask_api`.
- Unified API helpers live in `extensions.flask_api`; use `ok_response(...)`, `failed_response(...)`, `route(...)`, `class_route(...)`, `GetView`, and `PostView` for JSON APIs.
- API error responses must pass through the extension sanitizer before exposing details; it redacts absolute paths, URLs, token-like keys/strings, and raw HTML/RSS content.
- Keep the Web UI as a Flask server-rendered UI with minimal JavaScript; do not introduce React/Vite or a separate frontend build unless explicitly approved.
- Canonical Web UI homepage remains `/index`; root `/` should redirect to `/index`.
- Server-rendered UI assets live with the Web module under `src/apps/migu_orca_web/templates/migu_orca_web/` and `src/apps/migu_orca_web/static/`; serve pages through the `migu_orca_web` Blueprint and keep JSON APIs on `migu_orca_web_api`.
- Web API may accept `storage_dir` from query/body for local validation convenience; keep errors sanitized and avoid leaking absolute paths.
- Request query APIs live in `apps.migu_orca_web`; use `class_route`/`GetView`, return `{"requests": [...]}` for lists and `{"request": ...}` for detail, and keep storage access read-only through Stage 6 repositories.
- Web API mutation endpoints can reuse `apps.migu_orca_entry.controllers.entry_controller` orchestration; convert returned `success=false` error dictionaries into `Stage1Error` so `extensions.flask_api` produces the unified sanitized envelope.
- Use module-specific static URL path `/migu-orca-static/`; Flask's default `/static` route can mask colocated Blueprint assets.
- Request detail responses include optional `history` and `ab_result` sections; missing optional records should not fail the Request detail load, and damaged optional records should return section-local error metadata.
- Stage 9 browser automation should validate existing Stage 8 client-side DOM projections over current `/api/v1/requests` payloads unless a story explicitly requires test-only seams.
- Stage 8 browser-only preferences belong in `src/apps/migu_orca_web/static/app.js` with `localStorage` keys scoped to `miguOrca.web.*`; do not persist UI preferences through storage JSON or Web API payloads.
- Stage 8 Request list usability enhancements stay client-side over the `/api/v1/requests` summary payload; keep search/filter/sort in `src/apps/migu_orca_web/static/app.js` unless a later PRD explicitly adds backend search.
- Stage 8 page-level success/error feedback lives in `src/apps/migu_orca_web/static/app.js`; use `showNotification(...)` for user-visible operation results and `notifyApiError(...)` for sanitized unified API envelope failures.
- MiKan search and real-page RSS compatibility follow-up is tracked in `docs/backlog.md` and should not block Stage 9 browser automation unless explicitly pulled into scope.
- Playwright `fill("")` on an already-empty field is a no-op and does NOT trigger JS `input` events. Use `fill(" ")` (single space — trims to empty, triggers event) or `fill("   ")` to exercise blank-title form validation.
- Select list items by `[data-request-id='...']` CSS attribute selector; `has-text()` matches the rendered button label (e.g. the title, not the request_id).
- Browser page content always includes its own `<html>` tag — checking for `<html` to detect "raw HTML exposure" is a false positive. Check for `<rss`, URL schemes, and token patterns instead.
- `aria-relevant` attribute is on `#request-list-container`, not on `#request-list-panel` — validate the correct element.
- Pytest class names must start with `Test` (not `Describe`) to be collected; use `pytestmark = pytest.mark.browser` at module level for auto-skip.
- Flask Web UI runs with `uv run flask --app wsgi:app run`; validate code with `uv run pytest` and `uv run python -m compileall -q src`.
- Browser automation is the Stage 9 target. If browser binaries or browser MCP tools are unavailable in a Ralph session, record the limitation and preserve a documented manual fallback.
- Responsive/accessibility contracts are currently pinned in `src/apps/migu_orca_web/views_test.py` with static assertions; Stage 9 should add browser-level coverage for the same user-visible behavior.
