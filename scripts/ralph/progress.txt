## Codebase Patterns

- 本阶段只实现 B-C1：Auto Bangumi 3.1.18 capability、番剧/RSS 只读 adapter、安全投影、
  external mapping、严格对账、tracking sync、EXTERNAL_ONLY 与 VERIFY_EXTERNAL。
- 禁止实现或调用外部 create/modify/enable/disable/delete/refresh 等管理写动作；现有 Stage 29
  submit 创建路径只做兼容回归，不在本阶段改语义。
- 正式执行 PRD：`docs/MiGuOrca_stage30_ab_read_sync_PRD.md`；分支：
  `ralph/stage30-ab-read-sync`；stories：US-228～US-236。
- 3.1.18 已核实只读路径：POST `/api/v1/auth/login`、GET `/api/v1/status`、GET
  `/api/v1/bangumi/get/all`、GET `/api/v1/bangumi/get/{id}`、GET `/api/v1/rss`。
- password management client 必须一次登录、同一请求内复用同源 token Cookie，请求结束释放；
  API Token 管理读取和未知版本全部 fail closed。
- 原始 Bangumi/RSS 只存在 adapter/service 内存。完整 RSS URL 可用于当前同步的 exact 比对，但
  不得进入持久化、DTO、错误、日志、repr、trace 或 fixture 快照。
- 对账顺序：已保存 external ID > 正式标题+季度+字幕组（双方有 RSS URL 时追加 exact 比对）。
  只允许唯一候选自动关联；0 匹配建 EXTERNAL_ONLY；多匹配返回固定歧义，不选第一项。
- 外部孤立 ID 使用 PRD D30-09 的版本化 SHA-256 算法；request_id=null、origin=EXTERNAL_SYNC，
  不创建或伪造 Request。
- sync 读取任一失败不得把未知当空列表；逐条 ensure/CAS，部分失败不回滚健康项，永不删除本地
  Request、TrackingRecord、审计或媒体。
- Stage 29 `recover(AUTO)` 必须继续纯本地。只有新 `VERIFY_EXTERNAL` 接收 request-scoped
  ab_config 并调用只读 adapter；无/多匹配不证明外部未创建，不得直接变为可重试。
- Web API 继续按 `routes_*.py`/schemas/api_contract/serializer/service 分层；新增端点同步
  endpoint inventory、openapi_gen、openapi.json、TS generated client 与 contract tests。
- 外部响应 DTO 和 TrackingRecord nested mapping 必须严格白名单；绝不直接返回上游 dict。
- 每次迭代只完成最高优先级的一个未通过 story，提交后再把 passes 设为 true 并记录验证。
- 规划基线已手动切换时，`scripts/ralph/.last-branch` 必须与 prd `branchName` 一致；否则
  `ralph.sh` 会把新 PRD 误归档到上一阶段目录并重置 progress。本轮已同步为 Stage 30。
- US-228～US-235 只跑受影响定向测试、相关 ruff/compileall 和必要 drift check；US-236 才运行
  一次完整非浏览器、前端与 Chromium 门禁。禁止无修改重复跑全套。
- ExternalMapping v1 在 `tracking.py` 内严格校验；无 `schema_version` 的 Stage 29 legacy mapping 只做安全保留读取，不猜测迁移。
- 同步协调器构造本地对账 evidence 时必须排除 `EXTERNAL_SYNC` 投影记录，否则重复快照会把外部孤立记录自匹配并产生 revision/audit 漂移。
- tracking 默认列表必须过滤 `recovery.merged_into_tracking_id` 别名；详情的 external mapping 只能经安全 serializer 投影状态字段，不能回显 external/rss ID。
