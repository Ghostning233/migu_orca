## Codebase Patterns
- Stage 1 through Stage 5 are complete; archived Ralph records live under `scripts/ralph/archive/`.
- Stage 6 Ralph work uses branch `agent/stage6-request-persistence` and should complete one `passes=false` story per iteration.
- Use `uv run pytest` and `uv run python -m compileall -q src` for project quality checks; bare `pytest`/`python` may not be on PATH.
- Preserve the existing top-level JSON result envelope and convert expected business failures with `Stage1Error.as_dict()` or a compatible ErrorResult shape.
- Default CLI request generation must remain offline and fixture-backed unless the user explicitly opts into real external integrations.
- Default CLI request generation must not write local storage unless the user explicitly opts into persistence.
- Real external adapters should live behind engine-specific client/transport seams, with tests using injected fake transports instead of live network access.
- Request construction and confirmation logic live in `request_engine`; Stage 6 persistence should store snapshots/history without expanding Request domain rules unnecessarily.
- New top-level Python packages must be added to `[tool.hatch.build.targets.wheel].packages` in `pyproject.toml` so `uv run` installs them for CLI/tests.
- Stage 6 storage layout is centralized in `storage_engine.controllers.storage_config`; use `load_storage_config(...)` and `ensure_storage_layout(...)` instead of duplicating path conventions.
- Request persistence lives in `storage_engine.controllers.request_repository`; save/load complete Request dictionaries by `request_id` and keep error details to stable IDs, directory names, and filenames rather than absolute paths.
- Status history persistence lives in `storage_engine.controllers.history_repository`; append separate per-request JSON arrays under `history/` and keep transition metadata out of the saved Request snapshot contract.
- CLI Request persistence is opt-in via `--save-request`; use `--storage-dir` to override the default `.migu_orca/storage` root, and expose save metadata as top-level `saved_request`.
- Existing Request summaries are produced by `request_engine.controllers.request_controller.summarize_request(...)`; query/list views should reuse that contract where possible.
- Saved Request query paths should dispatch before generation in the CLI so list/load remains local-only and cannot touch MiKan, Auto Bangumi, or qBittorrent integrations.
- CLI real MiKan mode is explicit: use `--source mikan --mikan-config <path>`; default `--source static-fixture` stays offline and catalog-backed.
- CLI AB submission remains explicit: use `--action accept --submit-ab --ab-config <path>`; persistence must not implicitly submit to Auto Bangumi.
- Do not include raw HTML, raw RSS XML, complete endpoint URLs, cookies, tokens, or other sensitive config values in structured error details, logs, persisted errors, fixtures, or documentation examples.
- AB submit result persistence lives in `storage_engine.controllers.ab_result_repository`; write separate per-request JSON records under `ab_results/` only when `request.ab_submit_result` is an object from explicit `--submit-ab`.
- MiKan search and real-page RSS compatibility follow-up is tracked in `docs/backlog.md` and should not block Stage 6 persistence work unless explicitly pulled into scope.
