## Codebase Patterns

- 普通解析路径使用 `RuleAnimeTitleParsingProvider`；`FakeAnimeTitleParsingProvider` 仅用于显式测试注入。规则查询按 correction → alias → rule → fallback 排序，使用 NFKC/空白/casefold 去重，并限制为 8 条。
- Python 依赖、检查与测试统一通过 `uv`；Web 前端修改后运行 `node --check src/apps/migu_orca_web/static/app.js`，UI story 必须读取 `.agents/skills/dev-browser/SKILL.md` 并在真实 Chromium 验证。
- 标题解析结果只是搜索计划，不是真实 MiKan 候选；只有 M03 返回公开 `bangumi_id` 与规范化 `mikan_url` 的候选才可由用户显式选择并进入 preview。
- 单个 `/api/v1/mikan/candidates` 与批量 `/api/v1/batches/parse` 必须复用同一 parse → bounded query plan → candidate search 编排，不得复制第二套 MiKan parser、fallback 或候选序列化。
- 季数解析使用共享结构化原语，范围 1～99；无标记保持 null，冲突、越界、Part/分割放送等无法证明的表达必须人工审核，不得默认第一季。
- 跨模块季数判断统一使用 `shared.title_season.parse_title_season()`；它只返回可证明的 1～99 季数，保留原始 marker 供已接受元数据兼容，并提供稳定的中文规范化标题。
- 查询计划必须有界、稳定去重并保留来源/priority；高优先级查询有真实候选后停止弱 fallback，单条查询失败不阻断当前 item 的后续 fallback。
- 用户明确保存的公开 `TitleCorrection` 可优先生成搜索词，但不能自动选择 MiKan 合集；无修正、读取失败或规则低置信度时保留原始输入与 MiKan URL/ID fallback。
- parser 的 canonical title/season 是可审核提示。只有选中候选公开标题/元数据或用户显式确认能证明的 season 才能进入 Request、M07 命名和 M10 payload；冲突时保持审核并 fail closed。
- Web UI 的解析来源通过固定中文白名单展示；不要拼接内部 source code，也不要产生“源名称：搜索词：...”之类嵌套标签。
- endpoint、token、Cookie、Authorization、账号密码、raw HTML、raw RSS XML、magnet、原始响应体、完整失败 URL和本地绝对路径不得进入解析结果、查询计划、API、页面、storage、日志、截图或 trace。
- 浏览器测试使用 Playwright route/fixture 隔离外部依赖；运行完整 browser/full pytest 前确认仓库根 `.migu_orca/storage` 不存在。
- 每个 Ralph story 独立提交，只将当前完成 story 的 `passes` 改为 true，并在本文件末尾追加实现、文件和精确测试记录。
