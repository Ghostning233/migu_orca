## Codebase Patterns

- Python 依赖、检查与测试统一通过 `uv`；前端原生 JavaScript 修改后额外运行 `node --check src/apps/migu_orca_web/static/app.js`。
- Web UI story 必须使用 `.agents/skills/dev-browser/SKILL.md`，通过 `uv run pytest tests/browser/ -q` 在真实 Chromium 验证；外部 MiKan 通过 transport seam 或 Playwright route mock，不依赖实时网站。
- 单个与批量候选搜索必须复用 `_search_mikan_candidates`、公开候选序列化、候选缓存和现有 `mikan_bangumi` 详情到 preview 链路，不新增第二套 MiKan parser、筛选、命名或 Request 生命周期。
- 标题 `PARSED` 只表示解析完成，不等于找到 MiKan 候选或生成草案。Stage 22 前真实后端返回 `PARSED`，但 `canExpandBatchCard` 只允许 `DRAFT/READY`；现有部分浏览器 mock 使用 `DRAFT` 掩盖了该契约错误，后续测试必须使用生产状态形状。
- 真实候选结果必须区分 FOUND、EMPTY、FAILED；EMPTY/FAILED/PARSED 不得携带可接受的空壳 `preview_request`，只有用户显式选择公开 MiKan 候选并完成详情解析后才能进入 DRAFT/READY。
- 候选与结果 UI 只渲染公开字段和脱敏错误；endpoint、token、cookie、Authorization header、raw HTML、raw RSS XML、magnet、原始响应体、完整失败 URL和本地绝对路径不得进入 API、页面、URL、浏览器 storage、持久化、日志、截图或 trace。
- 搜索状态文案必须基于可观测事件；单一长请求只能展示请求级状态，不能用定时器伪造服务端页面解析或逐项进度。
- 工作台级 loading 锁定必须在恢复时还原控件原本的 disabled 状态，避免错误启用不可操作的卡片或提交按钮。
- 创建订阅方案工作台通过原生 `role=tablist` 分段切换单个/批量输入；结果应置于独立的整行 `search-results-panel`，并与当前模式同步显隐，避免两类旧结果混排。
- 单个与批量的公开 MiKan 候选卡复用 `renderCandidateCard`；批量卡片只有 `selected_candidate` 才能作为已选来源或主封面，绝不可把 `candidates[0]` 当作默认选择。
- 浏览器回归若需穿过真实 Flask 序列化和详情生成链路，可替换 `mikan_engine.controllers.mikan_client.create_mikan_client` 为携带假 transport 的真实 client；只模拟外部 MiKan 读写，不 mock 内部 API 响应。
