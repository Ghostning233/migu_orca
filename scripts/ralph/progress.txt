# MiGuOrca Ralph Progress - Stage 31

## Codebase Patterns

- 正式执行 PRD：`docs/MiGuOrca_stage31_ab_write_management_PRD.md`；分支：
  `ralph/stage31-ab-write-management`；stories：US-237～US-246。
- 本阶段只实现 B-C2 后端写管理，不实现 F-F 追番管理页面，不删除旧 API，不顺带完成 Stage 32 B-D。
- 只对 password + 精确 Auto Bangumi 3.1.18 开放写 capability；未知版本/API Token/探测失败全部
  fail closed。测试只用 recording fake，禁止访问真实实例。
- 固定 operation kind：MODIFY、SET_ENABLED、DELETE_EXTERNAL、REFRESH_RSS；公共目标只允许
  SUBSCRIPTION/ASSOCIATED_RSS，并始终从本地 tracking mapping 解析，不接受或返回外部 ID。
- 所有写入先 capability/read-before-write，再持久化 PREPARED、record current_operation_id 和
  IN_PROGRESS；完成这些边界前不得调用外部。相同幂等键最多一次外部调用。
- 写响应 2xx 后必须只读回查；timeout、连接中断、5xx、未知响应或回查失败保持结果未知，禁止
  换新 key 盲重试，只能 VERIFY_EXTERNAL/人工恢复。
- 番剧 disable/delete 的 `file=false` 必须由 adapter 常量生成，API schema 不得出现 file；禁止
  qBittorrent、文件系统或本地 Request/TrackingRecord 删除调用。
- 禁止 `/rss/refresh/all`、`/rss/delete/many` 和通用 method/path 代理；关联 RSS 只处理 operation
  启动时 mapping 中的有界 ID 集合。
- TrackingOperation v2 兼容读取 v1 SUBMIT；operation 只保存 kind/scope/status/摘要，不保存 patch、
  标题、外部 ID、URL、路径、凭据、请求/响应或异常原文。
- Web API 保持 routes/schemas/api_contract/serializer/service 分层；端点同步 inventory、
  openapi_gen、openapi.json、生成 TypeScript client 与 contract tests。
- 每次 Ralph 迭代只完成一个最高优先级未通过 story，完成定向验收并提交后才设置 passes=true。
- US-237～US-245 仅运行受影响定向测试和必要静态/drift 检查；US-246 才运行一次完整后端、前端与
  Chromium 门禁。禁止无修改重复跑全套。
- 若累计超过 12 次迭代仍未完成，停止循环并报告剩余 story/阻塞，避免无界 token 与测试开销。
- Stage 30 的 ExternalMapping v1、sync 幂等、合并别名、安全 serializer 与 VERIFY_EXTERNAL 语义是
  迁移基线；不可通过大重写破坏 Stage 29/30 兼容。
- Operation schema migrations may accept legacy v1 on read while omitting null v2 management fields from
  ordinary SUBMIT writes; management binding dimensions must be immutable in repository CAS.
- Pure management fingerprints/classifiers belong in tracking controllers with no web, storage, or transport
  imports; only the SHA-256 digest and outcome code cross durable boundaries.
- 3.1.18 management writes reuse the request-scoped password/Cookie session: authenticate, verify the exact
  version, call one fixed route, and clear the token in `finally`; destructive subscription routes build
  `?file=false` internally and never accept a caller-supplied query option.
- RSS enable-many is a JSON array body; adapter methods must sort/deduplicate mapped numeric IDs and inject
  the current request-scoped RSS URL for updates instead of accepting a caller URL.
- Management target resolution is a pure request-scoped boundary: resolve IDs only from the current local
  mapping and fresh snapshot, then persist only deterministic SHA-256 summaries.
- Management writes must bind the complete expected projection from the fresh snapshot, then terminalize the
  operation only after a matching readback; transport or evidence uncertainty remains recoverable.
