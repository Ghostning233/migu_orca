## Codebase Patterns

- 本阶段只实现 B-A：draft revision、可靠保存、单番/批量 save-confirm、36 部上限和 safe-info；
  不实现 tracking、Auto Bangumi 管理或新页面视觉。
- Web API 路由按 `routes_*.py` 注册；请求模型在 `schemas.py`，响应 DTO 在 `api_contract.py`，
  serializer 负责公开白名单，service 编排现有 engine/repository。
- 新增/修改 `/api/v1` 端点必须同步 endpoint inventory、`openapi_gen.py`、`openapi.json`、
  生成 TypeScript client 和契约测试；operationId 必须显式、可读、稳定。
- envelope 和 HTTP 分类继续使用 Stage 26 统一实现；错误不得包含 draft、原始 payload、完整 URL、
  magnet、凭据、上游响应、堆栈或本地绝对路径。
- Web `storage_dir` 只能是服务端根下的相对 profile；空值必须回落服务端 Web root，测试使用临时根。
- `draft_id`、revision、idempotency key 只存在请求体和页面内存，不进入 URL 或 browser storage。
- Python 使用 `uv`，前端使用 `npm ci`；自动化通过 fixture/fake transport，禁止访问真实外部服务。
- DraftStore 保存生命周期：`reserve_for_save(draft_id, base_revision)` → 持久化 → 成功
  `commit_save(draft_id)` / 异常 `release_save(draft_id)`；预留期间草案不可被 get/CAS/
  consume/update/逐出/过期处理，返回 `REASON_RESERVED` → 路由映射 409 `draft_reserved`。
- StorageConfig 目录以 `*.dir` 数据类字段给出（`requests/history/ab_results/queue/
  preferences/corrections/idempotency`），`ensure_storage_layout` 统一建目录；新增存储族
  必须同步 `storage_config.py` + `storage_config_test.py`。
- 幂等记录（US-213）模式：storage engine 的 repository 负责原子读写 + 白名单字段 + 路径安全
  （temp 文件 + `os.replace`）；`apps/migu_orca_web/save_confirm_service.py` 的
  `compute_request_fingerprint`/`run_save_confirm`/`resolve_in_progress_retry` 负责协议。
  记录文件 = `<storage>/idempotency/<opaque-key>.json`，字段白名单
  `idempotency_key/operation/request_fingerprint/request_id/state/created_at/updated_at`。
- save-confirm（US-214）接线模式：route 用 `services._build_save_confirm_persist_pending` /
  `_build_save_confirm_confirm_saved` + DraftStore `reserve_for_save`/`commit_save`/
  `release_save` 闭包注入 `run_save_confirm`。成功 = `{outcome: CONFIRMED, request, summary,
  handoff:{request_id, status: ACCEPTED, next_action: OPEN_TRACKING}}`（strict DTO）；确认失败
  （Request 已落盘）→ 409 `save_confirm_failed`，details 白名单只含 `outcome=SAVED_CONFIRM_FAILED`/
  `request_id`/`retry_action=ACCEPT_SAVED_REQUEST`。patch seam 要打实际调用命名空间：
  持久化失败 patch `apps.migu_orca_web.services.apply_request_save_action`，确认失败 patch
  `apps.migu_orca_web.routes_requests._build_save_confirm_confirm_saved`。
- 每次迭代只完成最高优先级的一个未通过 story；完整实现、测试和提交后才把 `passes` 改为 true。
- 批量行计数用 `batch_draft_controller.split_batch_raw_input`（create_batch_draft 与 route 共用）；
  服务端批量上限常量 `MAX_BATCH_ITEMS = 36` 在 `batch_engine/models`。新增 400 归类 error_type
