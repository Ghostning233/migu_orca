# MiGuOrca Ralph Progress - Stage 27

## Codebase Patterns

- 快照类 DTO（RequestSnapshotDTO/HistorySectionDTO/AbResultSectionDTO 等）用
  `_SnapshotBase(BaseModel)`（`extra="allow"`）让引擎 dict 可带额外字段过边界，同时给
  生成客户端稳定显示类型；envelope DTO 仍 strict `extra="forbid"`。视图运行时直接返回
  引擎 dict 不重序列化，OpenAPI 快照字段只是声明。
- 详情/子面板挂载模式：父视图 `v-if="selectedId"` + `:key` 重挂载，子面板自加载自管理
  loading/error/empty；`@changed` 通知父刷新列表、`@deleted` 由父清 URL 并卸载。
  动作成功后面板用服务端返回对象更新内存快照再重载，避免旧 app.js 双请求竞态。
- 破坏性/不可逆动作统一走共享 ConfirmDialog（confirm() 返回 Promise<boolean>，
  danger 用 .danger-button）；动作失败只显示固定中文反馈，绝不渲染服务端 error_message。
- 浏览器测试动作流程断言重载后状态用 wait_for_selector + to_contain_text 组合，避免
  命中重载前的旧面板（不要用会匹配旧面板的通用选择器如 .detail-actions）。
- `displayValue` 数组 join 用中文逗号 `，`；`scrubConfig` 里 key 命中敏感词
  （endpoint/url/token/...）优先整体 `[redacted]`，值 URL 检查只对非敏感 key 生效。
- `_ENDPOINTS` 的 `success` 优先写 pydantic DTO（如 `RequestListResultDTO`）而非 inline
  dict：DTO 让 OpenAPI 出现 title/required/additionalProperties:false，生成客户端类型更严格。
  改 DTO 后必须 `uv run python -m apps.migu_orca_web.openapi_gen` + `cd frontend && npm run
  api:generate` 并提交两个生成文件（drift check 双守护）。
- 生成的 `frontend/src/api/generated/api.ts` 里业务类型从 operations 内联提取，例如列表项：
  `NonNullable<operations['listRequests']['responses']['200']['content']['application/json']['result']['requests']>[number]`；
  `components.schemas` 只有 envelope DTO（ApiOkEnvelope/ApiErrorEnvelope），没有业务 DTO。
- 列表/表格类 feature 把纯函数逻辑收敛到独立模块（如 `features/requests/requestsList.ts`：
  label/search/filter/sort/status），feature 与 Vitest 共用，不复制第二套；状态码内部值只作
  option value 与内部比较，用户可见文案走 statusLabel 映射。
- 选择/恢复类状态由 URL query 驱动（`router.push({path, query})`），刷新恢复、清空时 push
  不带 query；`request_id` 等公开已保存标识符可进 URL，凭据/endpoint 永远不进 URL。
- 浏览器断言列表项用 `.request-list-item`（含 `data-request-id`）、选中用
  `.request-list-item.is-selected`，不要裸用 `[data-request-id]`（多处动作按钮共用该属性）。
- Vitest 里 `setValue` 后 computed 不重算，先怀疑 fixture 数据：多条 fixture 共享某字段
  （如 expected_folder_name）会让搜索命中多条；fixture 必须区分每条。
- `router.push` 是异步的：测试断言 URL query 用 `await flushPromises()`，不要单次 nextTick。
- `git diff --check` 会报 AGENTS.md 末尾多余空行：编辑后 `rstrip('\n') + '\n'` 归一。
- 迁移占位视图后必须同步 `tests/browser/test_app_shell.py` 的对应路由断言（旧断言引用
  占位视图的 id/class）。
- 工作台（US-204 起）候选/草案 feature 逻辑收敛到 `features/workbench/candidateSearch.ts`
  （校验/季数证据/payload 构造），候选卡片只渲染公开白名单字段；`candidate_context` 与
  `draft_id` 只存在组件内存，保存成功后 `router.push('/requests?request_id=...')` 跳转。
- 候选/草案公开 DTO：`MikanCandidateDTO` 用 strict `extra="forbid"`（engine 字段在边界拒绝，
  白名单见 test_dto_contracts 与 golden 测试）；`season_evidence` 用 lenient
  `SeasonEvidenceDTO`（`_SnapshotBase`）只作公开审核摘要。改白名单后必须重生成 OpenAPI +
  TS 客户端并同步 golden 白名单断言。
- 浏览器测试 SPA 通知断言用 `.global-notification:not(:empty)`（旧页是 `#page-notification`）；
  `page.route("**/api/v1/requests")` 只匹配精确路径，preview-modify/preview-save 仍走真实后端。
- CheckboxRow 的 id 直接落在原生 input：测试/浏览器用 `#mikan-fallback-enabled`（不要加
  ` input` 后缀），`v-model:checked` 绑定后 `setValue(true)` 即可触发显示/隐藏。

- US-200 起共享组件原语在 `frontend/src/components/`：layout（PanelSection/FormField）、
  forms（BaseButton/BaseInput/BaseTextarea/BaseSelect/CheckboxRow，v-model + attrs 透传 +
  aria-invalid）、feedback（ConfirmDialog/StatusAlert）；focus 用
  `app/composables/useFocusTrap.ts`，敏感凭据用 `app/composables/useSensitiveFields.ts`
  （字段只存组件局部内存，模式切换/成功/取消/卸载主动清空）。新 feature 必须复用这些
  原语，不得复制安全/确认/状态逻辑。
- ConfirmDialog 用 ref + `confirm({title,message,confirmLabel,cancelLabel,danger})` 返回
  Promise<boolean>；`danger: true` 渲染 danger-button。useFocusTrap 锚点放在 Teleport 根
