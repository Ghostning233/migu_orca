# Ralph Progress Log
## Codebase Patterns
- Web UI is server-rendered Flask under `src/apps/migu_orca_web/`; templates live in `templates/migu_orca_web/`, browser logic in `static/app.js`, and shared styling in `static/style.css`.
- Web API routes use `extensions.flask_api` class-based views and return the unified `{ok, result}` / `{ok, error_type, error_message}` envelope.
- Browser tests live under `tests/browser/` and use Flask live-server fixtures plus Playwright; run `./script/setup-browser-deps.sh` if Chromium or system libraries are missing.
- Real MiKan, Auto Bangumi, and qBittorrent configuration must remain explicit and request-scoped; do not write endpoint, token, username, password, cookie, SID, raw HTML/RSS, raw response bodies, or sensitive local paths to storage JSON, browser storage, URL, logs, screenshots, or traces.
- qBittorrent connection tests must call `POST /api/v1/qbittorrent/test-connection` and only render `status`, `reachable`, and `version` on success.
- Auto Bangumi submission must remain accepted-only and use `POST /api/v1/requests/<request_id>/submit-ab`; endpoint/token are temporary inputs and must be redacted from UI errors and persisted results.
- Stage 13 Auto Bangumi UI lives in Settings: accepted Request details link to `/settings?request_id=<id>#auto-bangumi`, and Settings owns endpoint/token/fallback inputs plus the return link to `/index?request_id=<id>`.
- Stage 13 UI work is not only route migration: `/index` and `/settings` must have clear visual hierarchy, consistent primary/secondary/danger button semantics, unified empty/loading/error states, readable medium/narrow layouts, and scannable Request detail sections.
- Stage closeout documentation should keep `README.md`, `docs/backlog.md`, `docs/modules/M13-web-ui-PRD.md`, `scripts/ralph/prd.json`, and `scripts/ralph/progress.txt` synchronized.
- Use shared Jinja includes for navigation shared across `/index` and `/settings`; pass `active_page` from Flask views for `aria-current` state.
- `/index` is the Request workbench: keep generation/list/detail there and move external data source, qBittorrent, Auto Bangumi submission, and other configuration tasks to `/settings` stories.
- Settings-owned non-sensitive browser preferences use `miguOrca.web.storageDir` and `miguOrca.web.saveRequest` in `localStorage`; `/index` should read those keys through shared JS helpers and must not render editable storage preference controls.
- Sensitive Settings forms should use collapsed `<details>` sections, guard JS initialization by element presence, require explicit `window.confirm`, and avoid localStorage/sessionStorage/URL persistence for endpoint, username, password, token, cookie, or SID values.
- `/index` URL state may use only `request_id`; after a flow renders a fresh detail payload, call `loadList({loadSelectedDetail: false})` so list refreshes do not overwrite that detail with stale or missing storage data.
- Request detail actions should use visible inline forms for extra input; modify clear operations use explicit empty strings in the existing restricted `filter_rule` / `expected_folder_name` patch fields, and browser tests should scope selectors to avoid action/form button label clashes.
