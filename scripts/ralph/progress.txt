## Codebase Patterns
- Stage 1 through Stage 7 are complete; archived Ralph records live under `scripts/ralph/archive/`.
- Stage 8 Ralph work uses branch `agent/stage8-web-ui-usability` and should complete one `passes=false` story per iteration.
- Use `uv run pytest` and `uv run python -m compileall -q src` for project quality checks; bare `pytest`/`python` may not be on PATH.
- Preserve the existing top-level CLI JSON result envelope and do not change the current `migu-orca` command behavior while adding Web UI usability improvements.
- Default CLI and Web UI Request generation must remain offline and fixture-backed unless the user explicitly opts into real external integrations.
- Default generation must not write local storage unless the caller explicitly opts into persistence through `--save-request` or the Web API `save_request=true` contract.
- Stage 6 storage layout is centralized in `storage_engine.controllers.storage_config`; use `load_storage_config(...)` and `ensure_storage_layout(...)` instead of duplicating path conventions.
- Request persistence lives in `storage_engine.controllers.request_repository`; save/load complete Request dictionaries by `request_id` and keep error details to stable IDs, directory names, and filenames rather than absolute paths.
- Status history persistence lives in `storage_engine.controllers.history_repository`; append/read separate per-request JSON arrays under `history/` and keep transition metadata out of the saved Request snapshot contract.
- AB submit result persistence lives in `storage_engine.controllers.ab_result_repository`; write/read separate per-request JSON records under `ab_results/` only when `request.ab_submit_result` is an object from explicit AB submit behavior.
- Existing Request summaries are produced by `request_engine.controllers.request_controller.summarize_request(...)`; API/list views should reuse that contract where possible.
- Real external adapters should live behind engine-specific client/transport seams, with tests using injected fake transports instead of live network access.
- Do not include raw HTML, raw RSS XML, complete endpoint URLs, cookies, tokens, absolute local paths, or other sensitive config values in structured error details, logs, persisted errors, fixtures, API responses, UI text, or documentation examples.
- Flask Web UI follows `/home/ghostning/github/user_level_flask` for structure: `src/apps/base.py:create_app`, `src/apps/registry.py:ALL_BLUEPRINTS`, module Blueprints, `extensions/flask_api` style response helpers, class-based `GetView`/`PostView`, Pydantic validators, `src/wsgi.py`, and Flask test client coverage.
- Flask blueprints should be exposed as per-module `blueprints` lists and registered centrally through `apps.registry.ALL_BLUEPRINTS`.
- Health endpoints return the target JSON envelope directly: `{ok: true, result: "ok"}`; Web JSON APIs should use `extensions.flask_api`.
- Unified API helpers live in `extensions.flask_api`; use `ok_response(...)`, `failed_response(...)`, `route(...)`, `class_route(...)`, `GetView`, and `PostView` for JSON APIs.
- `extensions.flask_api` converts `Stage1Error`, `APIException`, and Pydantic `ValidationError` into the shared response envelope; unexpected exceptions re-raise under testing/debug and become generic `internal_server_error` responses otherwise.
- API error responses must pass through the extension sanitizer before exposing details; it redacts absolute paths, URLs, token-like keys/strings, and raw HTML/RSS content.
- Keep Stage 8 as a Flask server-rendered Web UI with minimal JavaScript; do not introduce React/Vite or a separate frontend build unless explicitly approved.
- Canonical Web UI homepage remains `/index`; root `/` should redirect to `/index`.
- Server-rendered UI assets live with the Web module under `src/apps/migu_orca_web/templates/migu_orca_web/` and `src/apps/migu_orca_web/static/`; serve pages through the `migu_orca_web` Blueprint and keep JSON APIs on `migu_orca_web_api`.
- Web API may accept `storage_dir` from query/body for local validation convenience; keep errors sanitized and avoid leaking absolute paths.
- Request query APIs live in `apps.migu_orca_web`; use `class_route`/`GetView`, return `{"requests": [...]}` for lists and `{"request": ...}` for detail, and keep storage access read-only through Stage 6 repositories.
- Web API mutation endpoints can reuse `apps.migu_orca_entry.controllers.entry_controller` orchestration; convert returned `success=false` error dictionaries into `Stage1Error` so `extensions.flask_api` produces the unified sanitized envelope.
- Use module-specific static URL path `/migu-orca-static/`; Flask's default `/static` route can mask colocated Blueprint assets.
- Request detail responses include optional `history` and `ab_result` sections; missing optional records should not fail the Request detail load, and damaged optional records should return section-local error metadata.
- Stage 8 Request detail usability changes should stay as client-side DOM projections over the existing `/api/v1/requests/<request_id>` payload; do not change the saved Request snapshot schema for layout-only work.
- Web UI must scrub fallback config display values before rendering so URL-like strings and credential-like keys are redacted in collapsible JSON.
- Web UI form usability contracts are pinned in `src/apps/migu_orca_web/views_test.py` through server-rendered DOM assertions plus static `app.js` and `style.css` checks.
- Stage 8 browser-only preferences belong in `src/apps/migu_orca_web/static/app.js` with `localStorage` keys scoped to `miguOrca.web.*`; do not persist UI preferences through storage JSON or Web API payloads.
- Stage 8 Request list usability enhancements should stay client-side over the `/api/v1/requests` summary payload; keep search/filter/sort in `src/apps/migu_orca_web/static/app.js` unless a later PRD explicitly adds backend search.
- MiKan search and real-page RSS compatibility follow-up is tracked in `docs/backlog.md` and should not block Stage 8 Web UI usability work unless explicitly pulled into scope.
- Flask Web UI runs with `uv run flask --app wsgi:app run`; validate code with `uv run pytest` and `uv run python -m compileall -q src`.
- README is the canonical user-facing Web UI runbook; keep it in sync when changing Flask routes, API envelopes, storage defaults, UI workflows, MVP exclusions, or Stage 8 acceptance steps.
- Browser automation may not be exposed in Ralph sessions. If `dev-browser` is unavailable, record manual browser verification steps and any limitation in this progress file.
