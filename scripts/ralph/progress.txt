# MiGuOrca Ralph Progress - Stage 27

## Codebase Patterns

- Python 依赖、检查和测试统一通过 `uv`；前端依赖统一在 `frontend/` 使用 `npm ci`，不得混用 lockfile。
- Stage 27 只通过 `docs/api/openapi.json` 生成 TypeScript 类型/client；不得导入 Python 模型、手写第二套响应 interface 或从旧 `app.js` 复制业务状态机。
- OpenAPI 当前覆盖 24 个 operation 且 operationId 唯一，但 US-198 必须先修复运行时状态声明差异（Request 详情 404、海报 400/404/502）、生成器可读命名和自动一致性测试。
- 对应 feature 迁移前先补齐它实际读取的深层公开 DTO；长期 `dict[str, Any]` / `Record<string, unknown>` 不能作为完成状态。
- 新前端先挂载 `/app/`；SPA fallback 不能截获 `/api/v1`、海报、`/healthz`、`/readiness`、静态文件或旧 Flask 页面。
- production build 由 Flask 同源提供，不依赖 Node 运行时；Vite dev server 只用于本地开发代理。
- Pinia 只放跨页面非敏感状态且默认不持久化；candidate context、draft ID、搜索结果和敏感表单仅存在于内存。
- endpoint、username、password、token、cookie、Authorization、SID、raw HTML、raw RSS XML、原始响应体、完整失败 URL、magnet、本地绝对路径不得进入 store 持久化、URL、browser storage、日志、build、sourcemap、截图或 trace。
- 未保存草案由服务端 `DraftStore` 权威管理；前端只持有 opaque `draft_id` 和允许 patch，不得提交完整 Request 作为 preview modify/save 权威输入。
- Web storage 只能提交服务端根目录下相对 profile；空值回落服务端根。CLI 显式路径是不同信任边界。
- 单个与批量复用候选、草案、Request 和安全表单组件；不要复制后端标题、季数、筛选、状态或队列规则。
- 每个 UI story 必须读取 `.agents/skills/dev-browser/SKILL.md` 并用真实 Chromium 验证；浏览器整体 skip 不能作为完成证据。
- 浏览器测试通过 fixture/Playwright route fake 隔离外部服务；不得自动访问真实 MiKan 或向真实 AutoBangumi/qBittorrent 写入。
- 每个 feature 自己承担 DTO、Vitest、API contract、基本响应式/无障碍、Playwright parity 和敏感值回归；US-207 只做跨功能收敛。
- US-208 完成 parity 矩阵、默认入口切换和不回滚业务数据的回退演练；未通过前不得执行 US-209 旧资产删除。
- 完整门禁后确认仓库根 `.migu_orca/storage` 不存在，并检查未提交 build 临时目录和敏感产物。
