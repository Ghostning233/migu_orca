# MiGuOrca Ralph Progress - Stage 27

## Codebase Patterns

- US-200 起共享组件原语在 `frontend/src/components/`：layout（PanelSection/FormField）、
  forms（BaseButton/BaseInput/BaseTextarea/BaseSelect/CheckboxRow，v-model + attrs 透传 +
  aria-invalid）、feedback（ConfirmDialog/StatusAlert）；focus 用
  `app/composables/useFocusTrap.ts`，敏感凭据用 `app/composables/useSensitiveFields.ts`
  （字段只存组件局部内存，模式切换/成功/取消/卸载主动清空）。新 feature 必须复用这些
  原语，不得复制安全/确认/状态逻辑。
- ConfirmDialog 用 ref + `confirm({title,message,confirmLabel,cancelLabel,danger})` 返回
  Promise<boolean>；`danger: true` 渲染 danger-button。useFocusTrap 锚点放在 Teleport 根
  （backdrop）上，否则 inert 标错对象；浏览器测试查 `#app` 的 inert。
- BaseInput/BaseTextarea 必须自己 emit `update:modelValue` 才支持 v-model；Vue SFC prop
  不能用保留字 `for`（用 `inputId`）。jsdom 测 Teleport 组件用
  `attachTo: document.body` + `stubs: {teleport: true}`。
- CheckboxRow 等带包装 div 的组件必须 `defineOptions({ inheritAttrs: false })` 并手动转发
  `id`/`name` 到原生控件：否则 `id` 同时落在包装 div 和 input（Playwright strict mode 报
  2 元素）；`v-model:checked` 需显式 `checked` prop + `update:checked` emit。
- 连接测试/提交类表单（qB/AB）失败只显示**固定中文反馈**，绝不渲染服务端
  `error_message`（可能含 endpoint/凭据）；偏好等会拒绝敏感输入的表单失败时回退到
  「上次成功值」清空被拒绝输入（等价 legacy `currentPreferenceValues`）。
- Settings 等含多个 StatusAlert 的页面，断言必须限定到各自 form 作用域
  （`#xxx-form .status-alert`），裸 `.status-alert` 会命中第一个。
- 浏览器验证原语/迁移脚手架路由：`/app/components-demo`
  （features/components/ComponentsDemoView.vue，不加入导航），配套
  tests/browser/test_components_primitives.py；该路由在 US-209 删除。
- Python 依赖、检查和测试统一通过 `uv`；前端依赖统一在 `frontend/` 使用 `npm ci`，不得混用 lockfile。
- Stage 27 只通过 `docs/api/openapi.json` 生成 TypeScript 类型/client；不得导入 Python 模型、手写第二套响应 interface 或从旧 `app.js` 复制业务状态机。
- US-198 起类型化客户端由 `openapi-typescript@7.13.0` 生成：`cd frontend && npm run api:generate`
  输出 `src/api/generated/api.ts`（入库），`npm run api:check` 做漂移检查（CI frontend job +
  `tests/api_contract/test_openapi_runtime_consistency.py::test_frontend_generated_client_matches_openapi`
  双守护）。改 `docs/api/openapi.json` 后必须重生成并提交生成文件。
- `_ENDPOINTS` 每个条目必须显式声明可读 `operationId`（如 `listRequests`）；`errors` 声明
  必须与 `extensions/flask_api/api.py:_error_http_status` 运行时分类一致。
  `test_openapi_runtime_consistency.py` 自动核对：声明 vs 分类一致、被分类 error_type 全部有
  声明（CLI-only/批内 item 结果的进 `_UNDOCUMENTED_ERROR_TYPES` 豁免集）、operationId 唯一/
  可读/稳定、OpenAPI 无裸数组属性（列表写 `[Model]` 由 `_normalize_property` 展开）。
- openapi-typescript 生成模块是类型-only（无运行时值）：前端测试用 vitest `expectTypeOf`
  做编译期断言，不能 `import { operations }` 当值用；生成文件无敏感值（字段名除外）。
- 对应 feature 迁移前先补齐它实际读取的深层公开 DTO；长期 `dict[str, Any]` / `Record<string, unknown>` 不能作为完成状态。
- 新前端先挂载 `/app/`；SPA fallback 不能截获 `/api/v1`、海报、`/healthz`、`/readiness`、静态文件或旧 Flask 页面。
- production build 由 Flask 同源提供，不依赖 Node 运行时；Vite dev server 只用于本地开发代理。
- Pinia 只放跨页面非敏感状态且默认不持久化；candidate context、draft ID、搜索结果和敏感表单仅存在于内存。
