# MiGuOrca Ralph Progress - Stage 28

## Codebase Patterns

- 本阶段只实现 B-A：draft revision、可靠保存、单番/批量 save-confirm、36 部上限和 safe-info；
  不实现 tracking、Auto Bangumi 管理或新页面视觉。
- Web API 路由按 `routes_*.py` 注册；请求模型在 `schemas.py`，响应 DTO 在 `api_contract.py`，
  serializer 负责公开白名单，service 编排现有 engine/repository。
- 新增/修改 `/api/v1` 端点必须同步 endpoint inventory、`openapi_gen.py`、`openapi.json`、
  生成 TypeScript client 和契约测试；operationId 必须显式、可读、稳定。
- envelope 和 HTTP 分类继续使用 Stage 26 统一实现；错误不得包含 draft、原始 payload、完整 URL、
  magnet、凭据、上游响应、堆栈或本地绝对路径。
- Web `storage_dir` 只能是服务端根下的相对 profile；空值必须回落服务端 Web root，测试使用临时根。
- `draft_id`、revision、idempotency key 只存在请求体和页面内存，不进入 URL 或 browser storage。
- Python 使用 `uv`，前端使用 `npm ci`；自动化通过 fixture/fake transport，禁止访问真实外部服务。
- 每次迭代只完成最高优先级的一个未通过 story；完整实现、测试和提交后才把 `passes` 改为 true。

## [2026-09-07 23:38] - US-210/US-211 并发验收修复
Thread: current Codex project-management session
- What was implemented
  - 审计发现原 `compare_and_swap` 只有 revision 检查，没有并发锁；两个 Flask 请求可能同时
    读取同一 revision、同时返回成功并发生静默覆盖。现在 `DraftStore` 的 issue/get/CAS/
    consume/update/clear/len 全部通过同一 `RLock` 保护，revision 校验与替换成为单一临界区。
  - issue/CAS/update 入库及 get 出库均深拷贝 Request，避免调用方持有可变引用并绕过 CAS
    修改服务端权威草案。legacy update 同时补齐 TTL purge，过期语义与文档一致。
  - 新增稳定的真实线程并发测试：两个 writer 同时使用 base_revision=1 时，严格断言仅一个
    返回 revision=2/ok，另一个返回 revision_conflict；并新增读写快照隔离测试。
- Verification
  - `uv run pytest tests/api_contract/test_draft_store.py -q` → 16 passed
  - `uv run pytest -m "not browser" -q` → 1030 passed, 133 deselected
  - `uv run pytest -q` → 1163 passed（含 133 项真实 Chromium 浏览器测试）
  - `uv run ruff check src tests` → passed
  - `uv run python -m compileall -q src tests` → passed
  - 本次仅修改后端内存存储与 API contract 单测，无前端行为/构建产物变化。
- **Learnings for future iterations:**
  - revision check + replace 必须处在同一个锁保护的临界区；顺序 stale-write 测试不能证明 CAS
    在多线程 Flask 服务下具有原子性。
  - DraftStore 返回可变 dict 时必须返回隔离快照，否则调用方可在不增加 revision 的情况下改变
    权威 payload，破坏后续 US-212 reservation 与 US-213 幂等指纹的可靠性。
