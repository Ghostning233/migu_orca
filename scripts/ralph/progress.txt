## Codebase Patterns
- `modify_request` in `request_engine/controllers/request_controller.py` accepts both `PENDING_CONFIRM` and `ACCEPTED` requests and preserves the original status (never resets to `PENDING_CONFIRM`); accept/cancel remain restricted to `PENDING_CONFIRM` only via `_copy_pending_request`.
- Stage 14 has been completed and merged into `main`; current active work is Stage 15.
- `/index` remains the Request workbench and `/settings` remains the configuration/connection-test page.
- Saved-by-default generation is the normal Web UI contract; explicit `miguOrca.web.saveRequest = "false"` remains read-only preview mode.
- Preview Requests must not expose delete, confirm, cancel, modify, or Auto Bangumi submit actions.
- Storage request repository exposes `save_request_snapshot`, `load_request_snapshot`, `list_request_snapshots`, and `delete_request_snapshot`; all path-derived functions guard request_id through `_request_path` (rejects empty, path fragments, and traversal) and return stable sanitized errors.
- Web API request action endpoints share the shape `POST /api/v1/requests/<path:request_id>/<action>` with a `RequestActionPayload` subclass whose `request_id` comes from the URL path and whose payload only carries `storage_dir`; delete returns a safe summary (request_id, storage, directory, filename, deleted) and never the deleted snapshot body.
- Filter rules currently use `must_contain` and `must_not_contain` strings; Stage 15 should add `use_regex` and `case_sensitive` with default `false` and old JSON compatibility.
- Stage 15 filter default should be literal substring matching, case-insensitive. Regex matching must be opt-in.
- Request detail seed feedback should continue to derive complete/valid/excluded lists from the selected RSS source and must not render raw RSS XML or raw response bodies.
- Sensitive Web UI regressions should check URL state, `localStorage`, `sessionStorage`, visible body text, saved Request JSON, logs/screenshots/traces where applicable.
- Browser tests require the repo-root `.migu_orca/storage` to be absent; stale saved Requests there fail `test_empty_list_state`, `test_no_default_storage_pollution`, `test_list_count_shows_zero`, and the Stage 14 visual hierarchy test.
- Destructive Web UI actions (delete) require an explicit `window.confirm` gate; on success the front-end filters `loadedRequests`, calls `syncRequestIdToUrl(null)` to drop the URL `request_id`, clears the detail container to an empty state, then awaits `loadList` and shows the success notification AFTER the refresh (because `loadList` calls `hideNotification()` at its start).
- ACCEPTED Request details show 修改/删除/去 Settings 提交 Auto Bangumi; preview Requests must keep the existing read-only contract (no saved-action buttons and no saved-action API calls).
