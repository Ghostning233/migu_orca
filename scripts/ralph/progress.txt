## Codebase Patterns
- Keep learnings about this codebase in this file as iterations progress.
- Ralph defaults to the local Codex CLI; use `./scripts/ralph/ralph.sh` or pass `--tool codex` explicitly.
- Stage 1, Stage 2, and Stage 3 are complete; archived Ralph records live under `scripts/ralph/archive/`.
- Stage 4 Ralph work uses branch `agent/stage4-real-auto-bangumi-client` and should complete one `passes=false` story per iteration.
- Preserve the existing top-level JSON result envelope and convert expected business failures with `Stage1Error.as_dict()` or a compatible ErrorResult shape.
- Use `uv run pytest` and `uv run python -m compileall -q src` for project quality checks; bare `pytest`/`python` may not be on PATH.
- AB subscription payloads use the internal keys `title`, `rss_url`, `save_path`, and `filter_rule`.
- AB clients must expose `create_subscription(payload)` and go through `submit_ab_subscription(...)` to normalize success/failure into the stable submit result envelope.
- AB fallback JSON is opt-in via `submit_ab_subscription(..., fallback_enabled=True)` and is built from the prepared AB payload plus the structured failure reason.
- AB system config loading lives in `ab_engine.controllers.ab_config`, requires an explicit JSON path, and deliberately does not read environment overrides or include token values in errors.
- CLI AB submission is an explicit post-confirmation step: use `--action accept --submit-ab --ab-config <path>`; default generation and confirmation paths must not contact external systems.
- Stage 4 should replace the current fake-only CLI submission path with a real AB HTTP adapter while keeping fake-client injection available for tests.
