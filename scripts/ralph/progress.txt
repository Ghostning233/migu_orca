## Codebase Patterns

- Frontend API boundary types must be conditional aliases derived from `operations` in `api/generated/api.ts`; feature state models must not recreate API DTOs.
- Request-scoped journey capabilities and idempotency keys stay in component/composable memory; safe UI errors use fixed messages and allowlisted details only.
- Shared workflow state should be API-free; transport orchestration belongs in the later host story so single-anime and batch compatibility paths cannot accidentally share side effects.
- Single-anime search hosts invalidate candidate results as soon as the title changes, and apply result focus only after loading has been released so the loading rerender cannot steal focus.
- The single-anime review host owns the in-memory draft session and step navigation; save/confirm transport stays outside the shared editor until its dedicated story.
- The application shell owns the first direct-load keyboard stop (skip link); feature views only autofocus when mounted outside the shell.
- Atomic single-anime save-confirm hosts submit only generated capability fields plus a request-scoped idempotency key; the shared draft session is invalidated immediately after a confirmed handoff.
- Saved-confirm recovery must treat accept status conflicts as possibly completed: verify the read-only tracking list by the saved request_id before allowing any further action.
- Public handoff routes must sanitize mutually exclusive identifiers before mounting a feature; tracking detail renders only generated top-level safe summary fields and keeps batch queue mounting unchanged when no tracking identifier is present.
- Route-local leave guards should register browser unload protection only while mounted and make their router callback inactive on unmount, so feature capabilities cannot leak into later routes.
