# Ralph Progress Log
## Codebase Patterns
- Web UI is server-rendered Flask under `src/apps/migu_orca_web/`; templates live in `templates/migu_orca_web/`, browser logic in `static/app.js`, and shared styling in `static/style.css`.
- Web API routes use `extensions.flask_api` class-based views and return the unified `{ok, result}` / `{ok, error_type, error_message}` envelope.
- Browser tests live under `tests/browser/` and use Flask live-server fixtures plus Playwright; run `./script/setup-browser-deps.sh` if Chromium or system libraries are missing.
- Real MiKan, Auto Bangumi, and qBittorrent configuration must remain explicit and request-scoped; do not write endpoint, token, username, password, cookie, SID, raw HTML/RSS, raw response bodies, or sensitive local paths to storage JSON, browser storage, URL, logs, screenshots, or traces.
- qBittorrent connection tests must call `POST /api/v1/qbittorrent/test-connection` and only render `status`, `reachable`, and `version` on success.
- Auto Bangumi submission must remain accepted-only and use `POST /api/v1/requests/<request_id>/submit-ab`; endpoint/token are temporary inputs and must be redacted from UI errors and persisted results.
- Stage 13 UI work is not only route migration: `/index` and `/settings` must have clear visual hierarchy, consistent primary/secondary/danger button semantics, unified empty/loading/error states, readable medium/narrow layouts, and scannable Request detail sections.
- Stage closeout documentation should keep `README.md`, `docs/backlog.md`, `docs/modules/M13-web-ui-PRD.md`, `scripts/ralph/prd.json`, and `scripts/ralph/progress.txt` synchronized.
